## 固定左侧工具栏、缩放与显示字体（不修改报告内容）

- 缩放控件Portal至公共栏末尾，不再占纸面上方一行；正文独立滚动，公共栏在左侧卡片上方常驻。未选择内容时显示禁用的文字工具，字体值为空，不误改正文。

- 拖拽手柄在悬浮/选中/键盘聚焦时显示，触屏保留可见入口；减少动态效果偏好下关闭新增过渡。此批不做统一全文编辑器迁移，也未锁死工具栏两行。
- 人工验证：正文/标题直接输入、表头与普通格编辑、拖选合并/拆分、方向键/Enter、Excel粘贴、图片标题与管理卡片、拖拽与撤回；缩窄左栏确认按钮仍可见，核对选中前后图表没有尺寸跳动，PDF内容不变。

## 项目正文/表格行距与表后首空段修复

- 原因：Typst par.leading只计算同行段落内部的行间距离，单行段落/单行单元格的高度不会随它改变，和左侧CSS line-height的含义不一致。显式行距改为“内部leading + 首尾各半份leading”，同时保留段前/段后独立设置；无显式行距的旧正文仍沿用原路径。本节取代早前“单行不会有变化”的说明。
- 项目表格独占分区时，外层会吞掉表格above/below。显式整表段前后改由无额外块间距的外壳内padding承载，避免被吞或重复叠加。free_grid与普通报告表均有实际PDF坐标测试：段前/段后20pt分别增加20pt。
- 自由表格单元格/表头的真实换行转换为安全的linebreak，不再被Typst空白合并。单格行距覆盖字号规则在同一局部块内生效；测试覆盖独立表头、单行和多行单元格。
- 左侧报告单元格改为专用自适应输入框：数值、字号、字体、行距及列宽变化都触发高度重算，不卸载输入框、不修改单元格值，也不再以三行滚动窗口隐藏报告正文。原始记录/其他编辑器的AutoGrowTextArea不改。已明确设置的固定表格行高不会被此操作擅自清除，过小固定行高仍需用户调整。
- 表格后的首空段和后续备注位于同一编辑器时，Delete/Backspace现在也调用图表边界删除。只删除边缘空段，保留后续文字与段落样式，沿用表格末尾光标恢复；中间空段仍由正文编辑器处理。
- 验证：111项报告共享测试通过；新增实际项目PDF坐标测试覆盖独立文字段落、段内换行、分段文字、两种表格及表头。React回归覆盖首空段删除保留备注、改行距自动重算单元格高度且保持焦点。真实浏览器缩放/固定行高/跨页效果仍应人工核对。
- 手工：项目正文连续两行设行距0→1em；项目表格段前/段后分别0→20pt；单格输入两行文字，调整行距；选中整表调整行距；表后空段再接备注，首空段按Delete，确认备注保留、光标回到表右侧，再Enter可继续输入。保存重开及Ctrl/Cmd+Z一起核对。

## 图表边界、拖拽、复制与间距（2026-09-10）

### 本批实现

- 空段落删除：允许删除仅含空格、不换行空格、软换行的图表相邻段落；独立富文本与跨分区备注也接入边界删除。删除后定位图表边缘光标，Enter 可以继续输入；非空正文、签字和组合模块不删除。
- 拖拽：手柄以稳定字段 ID 标识来源，落点按目标块上下半部确定前后。支持同一项目、同一父分区范围内跨普通分区移动；落在连续正文上时插到该正文块前/后，不拆坏已保存正文。图片集合整体移动，保留集合 ID 与照片引用。受保护模块及跨项目移动拒绝，不修改数据。
- 整块复制：点击图表左侧手柄（也可在整块聚焦时 Ctrl/Cmd+A），Ctrl/Cmd+C 后在正文光标处或另一图表后 Ctrl/Cmd+V。复制使用当前显示值快照；粘贴分配新 ID，保留表格配置，移除活动数据绑定/公式，不重新拉取目标项目数据。单元格原有 TSV/Excel 复制不变。剪贴板仅携带当前页面内的不透明 token，不接收任意外部字段 JSON。
- 备注间距：有显式段前/段后属性时，替代对应旧字段外层间距；富文本外层不再额外继承分区 block gap。保留原字号、字体和未覆盖的旧间距。左侧正文容器取消固定附加段后距离，由文档段落与外层显式值控制。
- 公共栏补充整图表段前/段后（pt）、表格文字行距（Typst 额外 leading，em）。选中格/范围时应用到选中格，点击整块手柄清空格选区后设置则应用整表（含表头）；表格 CSS 与 PDF 共用 cell_styles.line_height。图片文字目前提供整块行距。

### 明确边界与后续工作

- 尚不支持单元格内仅部分段落、单个图片标题的局部行距；需要增加单元格/图片标题富文本模型与对应 PDF 转换，不能把当前“选中格”功能称为完整 Word 文本选区格式。
- 整块复制目前仅同一编辑页面内有效，刷新或跨标签页后不保证可粘贴；不接管外部 Excel 粘贴。独立旧 data_matrix 不支持整块复制，会提示。图片集合复制为报告自有图片块，照片/标题/尺寸保留，但复杂旧组合分区的外部标题、特殊边框和模块布局不承诺逐像素相同。
- 拖拽目前是块间重排，不是在一句正文的字符位置落图；字符位置插入请定位光标后粘贴。现有签字/模块保护继续保留。
- 验证：100项报告共享测试通过；React/jsdom 正文选区、空白删除、间距、表格键盘回归通过；实际 Typst 多项目 PDF 编译与保存形态 JSON 重开验证通过。前端构建和服务端类型检查通过。未做真实浏览器鼠标拖拽、系统剪贴板和逐像素 PDF 对照，不承诺不存在额外问题。

### 1. 图表边界的键盘行为

### 2. 表格无需预先解锁

- 常见结果/结论/设备/多样品/样品描述表以及 free_grid 统一使用稳定的 InlineReportTable 编辑入口；单元格始终可聚焦，第一次编辑前不生成快照、不标脏，实际修改时才保存报告内自由表格副本。
- 原始记录和模板不回写；free_grid 原映射保存在 instance_auto_free_table。首次修改和后续修改保持同一组件结构，避免切换 Auto/Free 组件造成输入框卸载。

## 自由表格合并区域结构安全（本批已实施）

- 根因：原增删操作仅修改行列数组，未维护覆盖区域跨度；删除只清理起始格的 span；设置跨度未做矩形重叠检查。
- 新增 shared/report-table-structure.ts，供生成报告自由编辑快照使用。内部插入时扩展跨越插入位置的合并范围；在合并边界之外插入不扩大范围；删除覆盖行/列时缩短跨度。未删除单元格沿用稳定 ID，不重排内容键。
- 删除合并起始行/列且合并还延伸到其他行/列时，提示先拆分；操作不改表格、不取消当前选择。这样不静默搬移主格值，也不覆盖被遮住的原值。普通删除仍会删除用户指定行/列中的数据。
- 合并校验整数范围、表格边界及其他合并矩形；相邻合并允许，交叠/包含其他合并格则提示先拆分。合并与拆分不清空隐藏格值。
- 范围限制：只接入生成报告的纯文本自由编辑表格。原始记录模板、录入试样区、映射配置和图片面板不变；未对历史已重叠的错误合并数据做自动清洗，也未自动迁移被删除的合并主格。
- 新增 8 项回归，覆盖两个轴、内部/边缘插入、删除跨度缩短、起始格删除保护、无效操作不改数据、重叠及越界合并、隐藏值保留与 JSON 重开。另跑前端构建、既有编辑器交互与实际 PDF 文档链路回归。
- 手工验证：建立跨三行/列的合并格，通过旁边普通格在合并内部插入/删除，核对覆盖范围；尝试删除合并起始行/列，应提示拆分且内容不变；尝试跨已有合并格再次合并，应阻止重叠。拆分后检查隐藏值，再保存重开并对比 PDF。实际浏览器新增结构交互仍需验收。

## 密度项目首改间距不一致与分区导航（本轮修复）

- 项目 PDF 渲染改为使用与 UI 相同的 reportTextRuns 投影；首页已有混合正文快照也使用该投影。只改变渲染副本，不写原绑定、不新增保存快照，签字区保持原路径。公共首页草稿及未转换的首页普通字段没有在本轮强行切换。
- 以实际密度项目模板构造“前两项已编辑、温度仍为带单位字段”回归：文本不变时，首次合并前后 renderContentDoc 输出完全相同；原文档打开/渲染不被修改。
- 同一项目内正文/图表到达分区边界时，方向键尝试进入相邻分区；正文设置实际选区，图表选中外框；不跨越签字锁定区或自动跳过空分区。跨项目导航尚未实现。

2. 打开报告时，原逻辑遇到模板更新会自动重建，即使报告已有人工修改。本批改为：有人工修改或连续正文时保留当前报告并提示手动确认；未编辑报告维持原自动更新行为。
3. 手动调整报告范围并重建时，不能继续带着旧的固定正文。重建首页先移除 `report_document`，从保留的源字段重新取值；此操作属于原有需确认的重算流程，不是后台静默刷新。
4. 前后端须同时更新；旧部署不理解本次段落覆盖和留白节点，不能直接回滚旧后端读取已保存的新文档。需要回滚时保留新格式读能力或恢复旧报告版本。

## 最新实施：可视化富文本正文

已将 ReportParagraphEditor 的 Markdown 输入框替换为 Tiptap/ProseMirror 正文编辑器。加粗、斜体（含组合）、列表、换行直接呈现，不再展示格式符；支持原生选区、正文内撤销/重做。仅启用 PDF 已实现的节点/标记，禁用链接、删除线、代码、标题等未统一渲染的扩展。表格/图片仍是文档独立块，通过正文工具栏插入，不嵌入正文 JSON。

新增带版本的正文编码 `@report-rich:v1:`，其内容为白名单文档 JSON，存于既有 rich 字段的 literal binding 中。旧 Markdown 打开时按原有 PDF 语法转换到编辑视图，不立即写回；用户编辑后才保存新格式。新格式由浏览器预览、PDF 和正文拆分共同消费，标记内的星号/特殊字符作为原文字处理；审计比较保留结构变化，但审计显示转为可读文字。未知/损坏的编码回退文字，不执行 HTML 或 Typst 代码。

安装生产依赖 `@tiptap/react`、`@tiptap/pm`、`@tiptap/starter-kit`，测试依赖 jsdom。集成参考 [Tiptap React 官方文档](https://tiptap.dev/docs/editor/getting-started/install/react)。未采用仍标注 Beta 的 Markdown 扩展；为兼容项目现有有限语法，使用独立版本化适配层，不把任意 HTML 当业务数据。

验证：真实 ProseMirror + jsdom 测试覆盖组合格式、撤销重做、光标拆分、段落/换行、列表、外部内容恢复及粘贴 HTML 过滤；14 项报告数据/渲染回归通过；真实 Typst CLI 已成功编译新富文本样例（含嵌套列表及特殊字符）。前端构建和前后端类型检查通过。尚未完成真实浏览器中文输入法、完整保存接口、上传和 PDF 视觉分页验收。

仍需后续：全篇跨块光标与合并操作、专用图片编辑器统一、正式送审/下载版本审核、最终浏览器视觉验收。此前章节的“编辑时保留 Markdown”描述已由本轮替代。

## 目标和边界
