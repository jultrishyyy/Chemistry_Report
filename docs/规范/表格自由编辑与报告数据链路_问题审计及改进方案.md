# 表格自由编辑与报告数据链路：问题审计及改进方案

审计日期：2026-09-07。状态：检查与设计完成，业务修复尚未在本轮实施。

本文作为后续实现和验收依据。核心目标是：用户像操作熟悉的表格一样编辑，系统负责保存数据身份、试样关系、公式依赖和报告来源。不能通过大量禁用按钮来掩盖链路缺陷，也不能用静默猜测换取表面上的自由。

## 1. 范围、证据与边界

本轮检查原始记录模板、矩阵/自由表格录入、剪贴板、实例结构、公式、报告模板拉取、绑定校验、报告生成和重算的相关代码。不是对账号安全、全部外部接口、设备管理、部署等整个系统的完整审计；本文的“问题清单”是本轮覆盖的数据链路内已发现的问题与风险，不能理解为穷尽所有缺陷。

证据等级：

- **A：运行复现。** 使用合成数据运行当前源码，记录实际与期望结果。
- **B：代码确认。** 当前分支明确存在相应行为或缺口，但未完成浏览器和数据库端到端复现。
- **C：待验证风险。** 有代码依据，需要补充组合场景、真实模板或接口验证，不能直接声称已造成生产错误。

本轮未连接生产数据库、未修改用户记录、未生成或发布真实报告，未做浏览器逐页视觉验收。已有大量工作区修改，本轮保留原样，仅新增本文和只读审计脚本。

只读复现入口：[`scripts/audit-table-flow.mjs`](../../scripts/audit-table-flow.mjs)。仓库根目录运行：

```sh
node --import tsx scripts/audit-table-flow.mjs
```

脚本输出实际值、期望值和 `matchesExpected`，无数据库及网络访问，退出码不代表业务测试通过。修复时将对应项目转成正式回归断言，不应通过改低期望值让审计“通过”。

## 2. 产品方向：取消要求用户“设置试样区”的工作流

### 2.1 用户不需要理解内部区域，但系统必须保存关系

不能仅删除“设为试样区”按钮而保留原来的配置前提。没有来源信息的任意 Excel 网格，无法可靠推断一组相邻数字究竟是不同试样、同一试样的重复测量，还是不同参数。自动识别可以减少操作，但不应在生成报告时重新猜测。

采用“自然操作产生关系”的方式：

1. 新建常见表格时显示“一行一个试样”“一列一个试样”“一个试样需要多行”等带示例的选择；也允许先自由画表。
2. 模板编辑器始终可用“预览 3 个试样”。常见表结构自动生成预览，用户通过真实展开结果理解行为。
3. 录入时提供“增加试样”“复制当前试样”“增加参数”“插入空白行/列”，内部自动创建相应身份和关系。
4. 复杂表第一次使用“增加试样”且系统不能判断时，在原表中突出候选内容，用一句业务问题“一个试样需要复制哪些内容？”配合预览完成一次确认。保存后无需重复设置；不再出现样品带、refs、cross_refs 等术语。
5. 用户直接插入空白行时先完成插入，作为普通内容保存。识别可能是试样时提供非阻断建议；只有要求它参与逐试样计算或报告而身份仍不明确时，才需要处理。
6. 用户导入外部表格时先完整保留内容，再识别标题、试样编号、参数与单位；未确定的少数项集中显示在侧栏，不连续弹窗。

不要把“设为试样区”简单改名为另一个必须学习的区域概念。底层可以继续存在重复布局定义，前台表达为用户正在做的事和展开后的效果。

### 2.2 可自由编辑的边界应由操作含义决定

| 用户操作 | 默认体验 | 系统责任 |
|---|---|---|
| 改字体、宽高、颜色、对齐、说明文字 | 立即生效，可撤销 | 不改数据身份和报告取值 |
| 移动/剪切已有数据到另一位置 | 数据和来源一起移动 | 维持原身份，更新布局及公式定位 |
| 复制一个试样 | 生成新试样，用户决定是否带数值 | 新身份，保留参数定义和公式规则 |
| 插入空白行列 | 立即插入 | 默认普通内容；不擅自增加试样或参数 |
| 增加预设参数 | 搜索勾选即可 | 自动带入单位、公式和报告规则 |
| 隐藏/停用参数 | 可恢复，保留原数据 | 隐藏、是否参与计算、是否输出分别记录 |
| 删除已有检测数据 | 允许发起，展示具体影响，可撤销 | 软删除或版本留痕，不复用旧身份 |
| 合并多个空格或说明格 | 直接合并 | 保持合理布局 |
| 合并多个有独立检测值的格子 | 简洁展示保留/展示方式 | 不得默认丢弃除左上角外的数据 |
| 修改报告绑定值 | 可编辑并显示来源状态 | 保存人工覆盖，不静默脱离来源 |
| 新增临时结果 | 直接填写 | 标记来源身份；仅在进入报告前补齐输出关系 |

“像 Excel”优先指熟悉的选区、键盘、复制粘贴、插入、移动和撤销体验，不承诺实现 Excel 全部公式、宏和文件行为。任意合并、覆盖、删除如果确实改变数据含义，必须保留足够信息或让用户作一次明确选择。

## 3. 当前链路与可复用基础

当前大致链路：模板版本 → raw_data/derived_data/实例表结构 → 各处计算与展平 → 项目模板绑定/结构快照 → 报告 content_doc → Typst/PDF。模板编辑、录入、原始记录渲染和报告渲染并非一个完整统一的表格运行时。

已有可复用能力：

- 矩阵有参数 code、sample_ids；自由表格有稳定行列 ID 和单元格键。
- 自由表格的本次结构保存在 `__free_table_structure__`，不必改模板。
- 记录有模板版本锁定；报告有 content_doc、原始内容快照、编辑标记与审计入口。
- 已有 `validateReportBindings`、跨表引用编码、数值修约和公式执行工具。
- 记录保存具备行锁、按字段补丁冲突检查；审核完成的数据已有限制。
- 前一轮已统一录入/粘贴布局和原始记录 PDF 的部分样品展开，并有 6 项回归测试。这不等于报告侧展开已统一；F01、F02说明链路仍有缺口。

## 5. 目标数据模型：数据身份与显示位置分开

### 5.1 四个概念，主要留在系统内部

| 概念 | 保存什么 | 为什么需要 |
|---|---|---|
| 数据身份 | recordId、tableId、sampleId、parameterId、measurementId/resultKind | 移动位置和改名字不改变“这个值是什么”；区分重复测量与新增试样 |
| 表格布局 | 行列顺序、宽高、合并、样式、单元格到数据的引用 | 能像 Excel 一样改变显示结构 |
| 计算与来源 | 公式引用、聚合集合、单位与修约、原值/人工覆盖 | 三处使用同一计算结果和解释 |
| 报告投影 | 本次包含的试样/参数、输出顺序、布局、来源引用和人工覆盖 | 报告可以不同布局，但按同一数据身份取值 |

稳定行列 ID 可以继续用于布局，不必马上废弃；新增独立数据身份，使剪切到别的行列仍指向同一个检测结果。没有业务含义的说明文字仍可以只是布局内容，无需强行给每个空格配置参数。

示例：参数“拉伸强度”显示在 B3，移动到 E7 后来源仍为同一个 parameterId；同一样品下第二次测量是新的 measurementId，不是第二个 sampleId。报告按 sampleId + parameterId + resultKind 取最终结果，不按 E7 取数。

### 5.2 值状态必须明确

建议统一解析结果包含状态、值、单位、来源和诊断。至少区分：未提供、明确清空、有效值、未启用、不适用、计算失败。数字 0、false 不得当作缺失。

只有“未提供”才可以按已定义规则采用默认值。明确清空不能恢复模板文字；计算失败不能默默变成空白或第一个试样。是否允许空白进入报告由参数/报告规则决定，而非渲染函数临时猜测。

### 5.3 统一执行链路

```text
锁定的模板版本 + 本次数据/结构操作 + 稳定试样/参数身份
                         ↓
               有效记录解析与依赖检查
                         ↓
                 统一计算结果及诊断
                  ↙               ↘
          录入/原始记录视图       报告投影与人工覆盖
                  ↓                    ↓
            原始记录 PDF             报告 PDF
```

模板、录入、报告共用结构命令和取值核心；各界面可以有不同工具栏。报告的独立排版不应强制跟随原始记录所有结构变化，提供“保留报告排版并更新数据”和“同步来源表结构”的明确选择。

## 6. 编辑命令、数据传播与交互细则

### 6.1 共用操作命令

建议建立共享命令层：插入/移动/删除行列、移动单元格、复制内容、增加试样、启停参数、合并/拆分、修改公式。每条命令先计算影响，再一次提交值、布局、引用和操作历史；失败时整体不应用。

- 移动保留身份；复制按含义创建新身份，不能把两个独立结果绑定为同一个对象。
- 内部复制携带类型、单位、来源和公式的结构化信息；外部纯文本粘贴只推断内容，不伪造可靠来源。
- 公式界面仍显示 A1/B2，内部表达式引用稳定身份；插入/移动后重算显示坐标。复制公式时区分相对/绝对引用，不能将移动语义用于复制。
- 删除使用可恢复状态；撤销恢复数据、绑定、格式、试样归属和公式，不能只恢复屏幕文字。
- 合并多个有值格时默认保留底层值；若选择只保留某值，显示具体影响并保留撤销记录。不要沿用 Excel 丢弃其他值的行为作为检测系统默认。
- 普通说明/格式变化不弹映射警告；删除唯一来源等真正有影响的动作，才显示具体对象和修复方式。

### 6.2 参数库与临时参数

第一版使用模板内参数目录，参数默认启用或备选。旧模板全部参数默认启用，保证兼容。一个参数可具有多格布局，不等价于单行或单列。

录入提供“添加参数”，常用项置顶、可搜索、多选；单位与公式自动带入。临时新增参数默认保留为本次数据，选择“进入报告”时使用已配置动态结果表或补充结果表；没有出口时列为待处理项，不自动猜映射。高频临时参数通过管理操作提升为新模板版本备选项。

停用不能直接删 cells。参与计算、界面可见、是否进入报告是不同状态；默认行为由模板给出，用户界面只在实际需要时展开高级选项。

### 6.3 报告对应关系的用户体验

录入侧栏显示业务状态：“会进入报告”“仅保留在原始记录”“待选择报告位置”，点击可定位参数。没有报告模板时显示“选择报告格式后检查”，不能显示假通过。

报告编辑支持点击结果查看来源并跳回对应记录/试样/参数。缺少映射与映射失效分开；缺少数据与不适用分开。优先提供“恢复参数”“改用此结果”“加入补充结果表”等直接动作，而非要求用户理解绑定编码。

### 6.4 保存和校验

- 草稿：允许不完整数据和暂未关联内容；不允许重复身份、非法跨度、越界结构等破坏性结构。
- 提交：检查必要检测数据、依赖和试样身份；已选报告格式时提前检查输出关系。没有报告格式不应无故阻止记录提交。
- 生成报告草稿：允许带清晰诊断的预览；不得将错误值伪装为正常结果。
- 正式确认/送审：依据实际报告范围检查必须输出项，明确阻止错取、缺失或未解决冲突。
- 所有规则服务端同样执行；已有审核锁、批次流程、协作冲突保护保留。

### 6.5 报告人工修改

用“旧生成基线、人工修改、新生成结果”做三方比较。文字、样式可保留；检测结果人工覆盖保存来源及覆盖状态。来源改变且同格有人工作改时列为冲突，不静默覆盖任何一方。用户主动选择重新同步模板时，预览将新增/移除的布局及覆盖影响。

## 8. 测试与验收矩阵

| 场景 | 必须验证的链路与期望 |
|---|---|
| 一个试样一行/一列 | 增加、减少、筛选、排序后身份和值对应；两种 PDF 一致 |
| 一个试样多行/多列 | 完整块顺序、每个试样内部合并、跨界共享合并正确 |
| 只输出第2、第4个试样 | 数值、公式、单位、名称取原试样；显示编号策略独立 |
| 多参数/重复测量 | 参数与测量次数不误认为新增试样，聚合集合正确 |
| 逐试样备注/判定/编号 | 改名不改变取值规则，真实编号不被流水号覆盖 |
| 清空/0/默认/不适用 | 全链路值状态一致，无默认文字复活或0丢失 |
| 插入/移动/删除/合并 | 引用稳定；有影响的操作明确诊断；撤销全量恢复 |
| 新增/停用/恢复参数 | 输入保留，公式依赖明确，动态报告纳入正确 |
| 临时新增结果 | 普通说明不打扰；必须报告项有明确出口或待办 |
| 跨表公式 | 不同试样顺序按ID对齐；缺失试样/循环/除零可诊断 |
| 外部/内部粘贴 | 换行、Tab、引号、选项、单位、公式、合并与来源分别验证 |
| 保存重开/批次提交 | 实例结构、试样身份、启用状态、审计快照一致 |
| 报告修改后重算 | 保留文字和样式，绑定值更新，覆盖冲突可处理 |
| 模板版本升级 | 老记录保留旧结果，新记录应用新配置，无静默迁移 |
| 两人编辑同表 | 同格冲突明确；不同格按既定策略合并，无数据覆盖 |

测试层次：公共函数单测 → 操作序列/不变量测试 → API集成 → 浏览器流程 → PDF实际输出。源字符串测试不能替代真实 PDF 验收。

不变量测试重点：身份唯一且不复用；移动前后来源一致；复制生成新身份；引用可解析或有明确诊断；合并覆盖不重叠；撤销恢复原快照；原始记录与报告对同一来源取值一致。

使用 `samples/originals` 中密度、透光率雾度、燃烧性、维卡等文件建立脱敏验收夹具；为每个文件记录保真项与不支持项。浏览器端至少跑“模板预览→试录→正式录入保存重开→报告模板拉取→生成→人工修改→重算”。

性能目标先测基线再定阈值；建议选10、50个试样及10、50、100个参数，记录键盘输入、粘贴、结构操作、保存、PDF编译的中位数/P95和内存。以连续编辑不被PDF编译阻塞为基本要求，不能仅以构建通过代替体验验收。

## 9. 兼容、上线与回滚

1. 先为旧数据实现只读适配，不就地批量重写用户记录。
2. 新结构增加 schemaVersion；sample/parameter 身份映射与旧键并存于适配层，不维护两套可独立编辑的事实来源。
3. 新记录写新结构，旧记录通过锁定版本适配。需要升级的记录生成可审查差异；无法确定试样关系的保持旧快照并列出诊断。
4. 分阶段开关：先修复取值与报告展开，再开放新交互；已经审核/送审的快照继续遵守既有锁定流程。
5. 若增加数据库列或索引，迁移需幂等、备份和独立验证。回滚必须仍能读新写数据，不能只回滚前端而让服务端无法解释数据。
6. 上线记录缺失引用、错位诊断、粘贴截断、重算冲突数量及失败原因；日志避免记录完整检测值和无关个人信息。
