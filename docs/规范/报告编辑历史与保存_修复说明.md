# 报告编辑历史与保存

## 原因

生成报告编辑器 handleSave 在成功后调用 replaceBaseline。每次手动保存和每 30 秒的自动保存都会清空 past/future，并将 baseline 改成最近保存内容。因此跨保存不能多步撤回，“回到刚进入时状态”也变成了回到最近一次保存。

原历史还仅按两次修改间隔是否小于 400ms 合并，可能合并快速的不同操作，或把长时间连续输入一直合并为一步。

## 修复

- 初次加载仍建立进入基线；普通保存改用 acceptSavedValue，保留 past、future、baseline。保存状态继续使用独立 savedDocSnapshotRef 判断。
- 服务端补齐的数据只在当前内容仍等于请求提交内容时接纳；若保存过程中有新输入，保留新输入并保持未保存状态。
- 撤回后自动保存不清除重做。重置仍可以撤回；重置回本次加载时的内容，不是生成报告时原始模板。
- 报告内点击、焦点切换结束上一个编辑分组。连续输入保留短时合并，但一个分组最长 1.5 秒，不无限合并。
- 历史仍保留最近 50 步，进入基线独立保存，不受 50 步上限影响。刷新、重新进入或显式重新加载报告仍开启新历史，不提供跨会话历史恢复。

## 验证

自动测试覆盖连续 4 次编辑和保存后多步撤回/重做、撤回后保存仍可重做、保存后重置、撤回重置、服务端补齐、延迟响应保护、快速不同操作分组、长时间输入分组。

手工：在报告副本中修改文字、单元格和字号，每次保存；连续点击撤回检查逐项恢复，再重做。等待自动保存后再次检查。点击重置应恢复进入状态，之后撤回应找回重置前内容；核对 PDF 同步及保存状态。旧版本已清空的历史无法由本修复找回。

## 原始记录模板、报告首页与项目模板检查

- 原始记录模板 handleSave 与首页/项目共用 useReportTemplateEditor.handleSave 原本只更新保存快照、草稿锁和版本元信息，没有在普通保存中调用 replaceBaseline，因此未发现同样的“保存即清空历史”问题。
- 三个页面补齐 pointer/focus 分组边界，保存开始时关闭当前输入分组，防止快速的不同编辑操作被合并。历史按钮在保存期间禁用；没有修改模板格式、字段、公式或映射数据。
- 版本元信息刷新以及开始/结束编辑不会主动重建历史。切换模板、只读版本、显式重载/恢复版本、新建后导航到正式模板地址仍属于重新加载边界，开启新历史。提交/审核等服务端版本流程不由本地撤回按钮反向执行。
- tests：scripts/test-template-history.cjs 使用三种模板形状的真实 React history，覆盖快速操作、保存间隔、多步撤回/重做/重置、公式图片保护，并检查三个页面的事件接线及保存函数不重设基线。该测试不替代连接服务端的全页面浏览器验收。
- 手验：三个编辑器各使用一个副本，修改名称、字体和表格并保存，依次撤回/重做；等待自动保存后重复验证；重置后确认回到本次加载内容，随后撤回应找回编辑。结束编辑再开始且未重新加载时历史仍应存在。
