# 多测试方法录入与结构化结论方案

## 1. 方案结论

不同测试方法继续使用独立的原始记录模板和项目报告模板，不把参数结构不同的方法强行塞进一份大模板。系统在模板之上增加“项目组”归类，在业务数据之上增加“录入批次”，解决模板过多难管理、公共信息重复录入和多记录重复审核的问题。

报告项目名称、子项目名称、判定要求和结论由原始记录中的结构化结论分区统一提供。报告项目模板只负责版式和数据映射，不再重复配置结论来源。

## 2. 核心模型

### 项目组与原始记录模板

- 项目组：例如“塑料弯曲性能”，用于归类相关原始记录模板。
- 测试方法：明确对应一份原始记录模板；报告项目模板在其自身编辑器中反向选择该原始记录模板。
- 一个原始记录模板最多属于一个项目组；项目组不区分基础模板，也不要求配置固定公共分区。

新建原始记录模板时可以不加入项目组、选择已有项目组，或直接新建项目组。项目组管理只负责修改名称以及加入、移出原始记录模板。

母子模板派生关系继续独立存在。项目组关系会与母子关系同时显示，但加入项目组不会自动创建派生关系。

项目组中的任意已生效模板均可作为同步来源。用户预览字段差异后，可选择同步到全部或部分同组模板。系统按字段标识或“字段编码 + 类型”匹配相同字段；目标模板专有字段不受影响。有未处理草稿、待审核或退回版本的模板会被跳过。同步结果进入目标模板各自的审核流程，不改写历史版本、已审核记录或报告。

### 录入批次

一个“委托单 + 样品 + 委托项目”只能建立一个当前录入批次。批次包含：

- 一份 `shared_data`，保存模板中标记为“批次公共字段”的数据；
- 多份独立 `record_data`，每种测试方法一份；
- 一次提交、一次撤回和一次审核状态；
- 每份原始记录仍保留独立模板版本、数据、审计快照和报告项目映射。

公共字段不以“复制第一份记录”的方式同步，而是只存一份并在各原始记录录入、预览、PDF和报告生成时合并读取，避免副本不一致。

### 报告项目组与主机厂

- 只有报告项目模板存在项目组；报告首页模板不加入项目组，继续独立管理和选择。
- 新建原始记录项目组时不再自动创建报告项目组，由用户在报告模板侧自行创建和维护。
- 同一个原始记录项目组可以建立通用或多个主机厂专用报告项目组，每个主机厂最多一个。
- 报告项目组统一关联主机厂；组内项目模板只读继承，不能逐模板覆盖。通用报告项目组的主机厂为空。
- 存量或未归组的独立项目模板继续在单模板层维护主机厂，保证兼容。
- 报告项目组可以设置一份已审核项目模板为基础模板并选择继承分区。派生项目模板完整复制基础版式、主动关联对应原始记录模板，并以草稿进入数据绑定确认和审核流程。
- 报告基础模板更新后沿字段映射为派生项目模板生成待审核版本；方法专有区块和历史报告不被覆盖。
- 报告工作台以首页模板主机厂优先推荐相同主机厂的项目模板；无专用版本时通用报告项目组作为默认回退，用户仍可显式改选。

### 结构化结论分区

“结论”是一个模块（`FieldGroup`），不是一个复合字段。模块里的项目名称、判定要求和结论均为普通独立字段，各自拥有稳定字段编码，并分别保存到 `record_data.raw_data[field.code]`。

1. 整体项目：顶层结论模块默认包含“项目名称、判定要求、结论”三个独立字段。
2. 子项目：点击“添加子项目”后创建结论模块的真实子分区；每个子分区默认包含“子项目名称、判定要求、结论”三个独立字段。

项目名称和子项目名称是模块的必要字段，不能删除，但录入人员可以修改其本次记录值。顶层判定要求和总结论可分别删除或重新添加；每个字段仍可独立配置必填、默认值、说明和格式。

结论字段允许在“文本”和“选择”两类之间切换。选择类型可以配置“符合、不符合”等选项及是否允许自定义；切换类型时保留其 `conclusion_role`，不会断开报告映射。

字段流转规则如下：

- 无子项目：报告首页检测结论表和项目报告的项目名称、结论均取整体结论项。
- 有子项目：报告首页检测结论表按子项目逐行显示“子项目名称 + 子项目结论”；项目报告标题始终取总项目名称。
- 项目报告结果表中标记为结论列（列名为“结论/判定结果”，或使用结论格语义标记）的格子自动取结构化结论。子项目模式优先按行取对应子项目结论；跨行总结论格优先取录入的总结论，未保留总结论时按子项目结论汇总。
- 报告实例把自动结论表转成自由编辑表格时仍按以上规则冻结当前值，子项目名称不会退化为总项目名称。
- 旧版 `record_conclusion` 复合字段继续只读兼容和生成报告；新建字段菜单不再提供该类型，新模板统一使用模块化结构。

## 3. 业务流程

1. 模板管理员制作原始记录模板时可选择或新建项目组；需要复用字段时，由任意已生效模板向选中的同组模板发起同步。
2. 原始记录模板把重复字段标记为“批次公共字段”，并配置一个结构化结论分区。
3. 工程师在委托项目下批量选择一种或多种测试方法，系统创建一个批次和多份原始记录。
4. 任一原始记录录入的公共字段都写入批次；切换到其他方法时自动显示。
5. 工程师填写每种方法的专有参数和结论模块中的独立字段；在草稿或整批退回阶段可继续追加兼容的测试方法，然后提交尚未通过的记录。
6. 审核员可逐份预览并勾选审核：既可整批处理，也可让部分记录通过、部分记录退回。已经部分通过后，共享公共字段锁定；如需修改公共字段，审核员须把已通过记录一起退回，避免已审数据被静默改变。
7. 报告生成按每份已审核原始记录查找主动关联它的项目报告模板；首页结论表按结论模块的整体项目或子项目结构展开。

## 4. 兼容规则

- 存量原始记录没有结构化结论字段时，继续使用原项目报告模板的结论绑定。
- 未纳入测试方法管理的原始记录仍可按原有单模板方式录入、提交和审核。
- 标记为批次公共的字段在单独录入时仍保存到该记录自身，不会丢失。
- 同一原始记录模板存在多个生效项目报告模板时，继续保留报告工作台的候选选择能力；项目组不参与该选择。
- 报告项目模板关联只允许从报告项目模板侧主动选择 `linked_record_template_id`；原始记录项目组不维护报告模板关系。
- 数据库强制只有 `template_kind='project'` 的模板可以设置 `report_project_family_id`，首页模板即使绕过界面也无法归组。
- 已审核记录继续按录入时锁定的原始记录模板版本回放。
- 旧版多公共组件表和模板快照暂时保留作存量兼容，但新界面不再提供提取、插入、发布和拉取公共组件的入口。

## 5. 当前实施边界

- 创建批次时可以一次选择全部测试方法，也可在草稿或整批退回阶段追加方法。
- 待审核或已经部分通过时不能直接追加方法；需要先完成撤回/退回，保证审核范围明确。
- 草稿或整批退回阶段可以把已有方法标记为“取消检测”。取消原因必填；原始记录、已录数据、附件、模板版本和审计记录全部保留，但该方法不再参与提交、审核、批次状态汇总及报告生成。
- 取消检测采用逻辑状态，不提供物理删除，保证检测范围变化可追溯。
