# 试样区域继承与项目模板映射简化：实现说明

日期：2026-09-08。以本文件为最新产品约束；早期审计文档中“取消原始记录试样区域”“动态新增参数自动进入报告”的建议不再作为本轮实现目标。

## 1. 已确定的行为

- 原始记录模板保留框选试样区域和行/列方向设置。
- 项目模板拉取表格时继承来源、方向、试样块和逐格绑定。用户不再先点“按每个试样取值”再选来源。
- 项目模板拉取后默认沿用原始记录排列。取消自由表格的转置功能及相关提示；保留试样按行/按列设置及两种方向的渲染能力。既有模板按保存的布局读取，不自动改回或迁移。
- 绑定由稳定 field_code/cell_key 和当前试样决定，不依赖表头名称。表头文字、数据结果、公式结果、单位仍有不同内部来源类型，但不要求用户选择内部类型。
- 选择/清除来源只影响目标格及其单位，不自动合并其他格子，也不把一个格子的绑定广播到整条参数轴。
- 普通新增行列不自动带入报告；保持生成阶段警告。已有报告成品不自动重写，修改后需显式重新生成。

补充约束：新建记录中，试样区域的每行（按行）或每列（按列）就是一个试样；新增一次只复制一行或一列的配置，不再复制整个区域。试录测试和正式录入直接提供新增/删除试样操作，不需开启“调整结构”；普通行列编辑才进入“调整结构”。任意位置插入普通行列时的完整依赖维护、普通新增内容的确认持久化仍是后续工作。

## 2. 核心风险与处理

| 风险 | 处理 |
|---|---|
| 只选第二个试样却取第一个值 | 过滤保留原始试样索引；单位和公式同样按原索引取，显示编号单独处理 |
| 多行试样报告顺序不同 | 报告共用完整试样块的布局计划与合并跨度，不再单行分别复制 |
| “备注/平均/编号”文字决定绑定类型 | 移除禁止性正则；按明确区域关系和显式序号标记判断 |
| 同一试样内部多行合并被视为共享结果 | 只有合并跨出试样成员/精确范围时视为共享；完全在块内的合并允许逐试样 |
| 清除映射或选来源导致表格合并改变 | 移除虚拟合并及跨格传播，只保留模板实际 spans |
| 点表头本想取标题却取数据 | 标题格优先关联标题；逐试样目标可直接点试样数据格，标题快捷入口仅在没有“标题取值”模式时启用 |
| 选择无单位的新来源却残留旧单位 | 自动跟随来源时同步清除旧单位绑定；显式手动单位仍可再次配置 |
| 历史项目模板包含旧式错误绑定 | 不批量猜测或改写，现存绑定原样加载；新拉取应用新规则，旧模板可逐格重新选择来源 |
| 不同试样区域或表格交叉绑定 | 默认仅列出当前继承来源表；不能默默用A表试样数读取B表 |
| 自由表和矩阵路径不同 | 矩阵来源仍保留配置入口，但改为“试样来源/向下排列/向右排列”；验证矩阵取值未回归 |

不能承诺对所有存量模板没有排版变化：修复多行展开和移除虚拟合并后，编辑画布会展示实际单元格结构。已保存的 PDF 不受影响，重新生成的报告可能纠正旧顺序。历史人为利用旧错误顺序排版的模板需对照验收。

## 3. 实现文件和步骤

### A. 共享来源语义

新增 `shared/free-grid-binding.ts`：归一化旧/新试样区域；判断单元格是否为有效逐试样来源；生成单格来源和单位绑定。显式序号标记优先，任何标题文字均不自动决定检测值身份。被合并覆盖的格不是独立来源；跨边界主格只能固定取值。模板拉取和来源选择器使用同一规则。

### B. 报告展开

扩展 `buildFreeGridLayout` 接收可选试样索引列表，默认行为保持录入兼容。报告将来源区域转换为布局计划，映射显示行列、数据和合并跨度；筛选后的 sample 是原索引，不是显示序号。空过滤不回退所有试样。

`expandFreeGridBand`：固定格和逐试样格都复制布局，但只对逐试样绑定解析当前试样；同一原始来源块中的固定格保持同值。单位、人工公式修正按同一个 sample 读取。数据优先级使用空值合并而非排除空字符串。

### C. 自动拉取

`report-inherit.ts / convertFreeGrid` 使用共享语义生成绑定：标题→标题文字；试样数据→逐试样；公式→原记录公式结果；明确序号→自动序号；其他→固定来源。保留实际 spans 和 source_field/source_band_id。不转换已保存项目模板，仅影响重新拉取。

### D. 选择来源交互

`FreeGridCanvas.tsx`：删去二次开启逐试样的按钮和 pending 状态；目标位于继承试样区时自动允许逐试样来源。非逐试样目标维持固定取值。用“选择来源”“清除来源”代替技术表达。明确显示来源表、向下/向右展开、每份所占行列数。

移除 `lockedVisualSpan` 和 `spanRectAt` 中的虚拟合并；选区仅跟随真实 spans。绑定写入只写当前主格。真实合并多个不同来源仍保留现有明确选择流程。

`BindingPickerModal.tsx`：支持直接点击试样数据格；不按“备注/平均”等文字禁选；选中高亮指向准确来源格，而非把一个参数轴上多个独立结果都标成相同来源。内容和单位在一次保存中更新。

### E. 兼容与验证

不做数据库迁移，不重写原始记录，不改变模板版本锁定和报告审批流程。共享模块使用 TS 源码；前端构建之外还要检查服务端带 `.js` 的入口是否误用残留产物。

## 4. 验收

- 行/列两种方向、一个试样多行/多列、试样内部合并、跨边界共享格。
- 全部、仅第2个、非连续、空筛选；值、公式人工修正、单位同步正确。
- 备注/判定/平均值可以逐试样；实际编号不被文字猜测覆盖。
- 明确空值、零值、模板默认值、选择“其他”、无单位来源切换。
- 绑定前后 rows/columns/spans 完全不变；清除一个来源不清其他格。
- 拉取一次后可直接修改来源，不需“先设为逐试样”；旧固定来源仍可查看和保留。
- 原始记录的既有6项布局回归不退化；新报告链路测试和前端构建通过。
- 浏览器/PDF实际对照若环境未具备，应明确标为未完成，不能用源码测试宣称视觉验收完成。

## 5. 实施记录

2026-09-08补充：已删除自由表格的“转置选区”入口及完整操作函数，清理模板/报告编辑相关提示。试样按行/按列设置及既有布局读取、渲染保留；未修改业务数据。组件静态验证覆盖原始记录和项目模板均无转置入口、两种方向加载时结构和绑定不变；17项链路回归（含实际PDF编译）及前端构建通过。未执行浏览器人工交互验收。

本轮已实现：

1. `free-grid-binding.ts` 统一显式试样区域、合并主格、边界和序号语义。拉取转换与点格选择不再通过“备注/平均/编号”等文字猜测。
2. 报告采用共享样品块布局；修复筛选后数值、公式人工覆盖和单位取错试样；保留明确空值。
3. 拉取后的项目模板自动允许试样来源，移除“按每个试样取值”前置按钮。来源只写当前格，取消虚拟合并和整轴广播。
4. 直接点试样数据格即可选来源，单位同步关联或清除；标题仍可独立选择。
5. 校验补充逐试样公式/单位的目标区域和来源区域检查，并识别旧 source_band_id 已不存在的情况。
6. 服务端项目模板拉取及绑定校验明确加载 TypeScript 源文件。运行复核确认同名旧 `.js` 与 `.ts` 并非同一导出，不能继续依赖隐式解析。

## 6. 录入操作补充实施（2026-09-08）

此前文档不等于全部实现：当时仍使用“样品数”及整块展开，所以试录中没有独立新增按钮。此次补充的实现如下。

### 交互

- 共用 `FormRenderer` 的试录测试、正式录入：新增试样行/列统一放在表格上方工具栏，不受表格横向滚动影响。
- 删除操作仅在灰色行号/列号的右键菜单中显示，选择后再次确认；不显示常驻删除文字或图标。试样增删无需开启“调整结构”。
- 删除旧“样品数”加减入口；一次只增加一行/列，沿用末个试样的格式、单位选项和公式配置，输入值清空。最多50个可见试样。
- 普通插入等操作仍放在“调整结构”内，不因试样增删进入该模式，也不将试样增删误记为普通结构变动。
- 允许删到零个并保存草稿，显示提示；服务端提交校验拒绝零试样及非法试样轴信息。已有无显式轴信息的历史记录不新增此校验限制。

### 数据与报告

- `shared/free-grid-samples.ts`：用 `__sample_axes__::<区域ID>` 存储有序 `{ref, sample}` 列表；ref为原型行/列ID，sample为稳定的值存储槽位，不是当前显示序号。`__sample_next__::<区域ID>` 保证删除后新增不复用旧槽位。
- `matrix-flatten.ts / buildFieldDefaults`：新建记录和试录的初始列表对应模板区域现有行/列，原有输入值键仍可使用。
- `free-grid-layout.ts`：录入和PDF共用显式轴布局。旧记录没有该列表时仍按原有块计数读取；第一次增删时将当前显示轴转换为列表，保留原值，不做批量迁移。
- 删除保留旧值但从活动列表移除，避免其他试样串位；界面和报告只读取活动试样。显示序号重新连续编号，不重编号底层存储键。
- `typst-generator.ts`：继承报告按活动轴数量展开，根据ref和稳定槽位读取数据、人工公式修正和单位；筛选按活动列表位置解析。显式轴的非自定义汇总公式排除已删除试样，所选单位同步到原始记录PDF。
- `record-data.ts`：现有单笔/批量提交的校验路径追加试样轴检查。无需数据库迁移，不修改已生成报告。

### 局部区域与多区域检查补充

- 局部矩形通过 `refs + cross_refs` 保存，并非只能设置整行/列。组件静态测试覆盖两个方向的完整/局部区域，四种情况均显示新增和紧凑删除入口；用户反馈的局部区域无按钮尚未复现，需要实际模板配置进一步定位。
- 当前布局扩展仍作用于整条物理行/列，`cross_refs` 主要限定逐试样取值范围；不能将此解释为“矩形内部独立增删、外侧几何完全不变”已实现。
- 当前仍限制单区域：共享布局以首区域决定方向、同一轴ID只关联一个区域；报告 `getMatrixFreeBand` 只选择首个报告驱动区域。因此不能仅删除前端限制就宣称多区域完整支持。
- 产品建议（尚未实现）：普通表通过行号/列号选择试样成员，局部框选保留为复杂表入口。多区域应先明确是否共用同一试样列表，再补充按区域展开、绑定与筛选、共享/独立增删及跨区合并校验后开放。

### 录入UI与区域设置补充

- 当前产品决定仍是一表一个试样区域，不开放多区域。设置后只显示区域范围、方向和“清除试样区域”，清除后才重新出现“设为试样区”。区域工具栏不再依赖当前是否有选区，避免确认设置后清除入口随选区消失。
- 区域方向确认由容易忽略的内联栏改为弹窗，明确显示所选矩形范围、方向、初始试样数，确认后提示成功；仅框选而未确认不会写入区域。
- 新增入口统一置顶，消除按列按钮在宽表右侧滚动范围外的可见性问题。回归测试包括周围仍有普通行列的内部局部区域，以及配置JSON重载；两种方向均显示顶部新增入口。尚未获得用户出问题的实际模板，不能断言已定位其唯一根因。
- 定位蓝条的字段容器增加固定内边距及最小宽度约束，内容与蓝条分离且焦点切换不改变间距。按键说明与模板编辑说明改为问号悬浮帮助。
- 组件静态测试检查顶部新增、关闭的右键菜单无常驻删除按钮、操作帮助收起、区域设置/清除互斥。真实浏览器右键菜单点击、悬浮帮助和视觉对照仍需人工验收。

### 结构调整公共编辑栏补充

- 进入“调整结构”直接打开工具栏，不弹进入确认、不显示常驻结构警告。工具栏为新增行、新增列、删除行、删除列、合并、拆分，以及字体、字号、加粗、斜体和对齐。
- 新增默认在选区下方/右侧；无选区时追加到末尾。若插入线穿过已有合并格，顺延到合并格之后，避免改变原合并关系。不再分别提供上方/下方、左侧/右侧入口。
- 删除仅允许新增轴；合并、拆分仅允许全部由新增内容组成的选区。选区自动包含完整合并格，涉及任何原有结构时统一提示“原表格结构不可修改，仅能新增行/列并对新增内容进行修改。”
- 合法的新增、删除、合并、拆分不弹确认；删除新增轴时同步收缩相关新增合并格。试样增删继续使用独立入口，不受上述普通结构限制。
- 格式设置对原有及新增单元格均开放，写入本次记录的表格样式，不写入模板；仅调整格式不新设结构变动标记。修改后保持选区，可连续配置字体等外观。

### 生成报告时提醒表头改名

- `record-header-changes.ts` 将当前活动表头与原始记录锁定版本中的模板文字比较，包括普通表头覆盖值、新增试样的独立表头及实例表格文字。不以结构变动标记判断，不使用表头名称定位映射。
- 修改名称或清空名称会产生 `record_free_grid_header_changed` 警告，保存表格名称、稳定格ID、试样槽位、修改前后文字。只改字体、恢复原名、已删除试样的残留值不触发警告。
- 公共报告构建流程收集警告，报告预览与结构化编辑页面显示修改前后名称并提醒核对对应数据；不阻止生成，不修改现有映射，也不代表已完成新增试样表头的报告自动同步。
