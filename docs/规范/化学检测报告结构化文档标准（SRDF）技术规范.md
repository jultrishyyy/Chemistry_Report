## 商业与合规价值摘要

> **一句话定调.** SRDF 是一套企业自主标准，把化学部的检测数据从易追责、易流失的纸面与普通数据库资产，升级为**防篡改、完全可追溯、可自证清白的数据资产防火墙**。

### 今天的风险敞口（这是业务与法律之痛，不是技术问题）

- **法律追责风险.** 检测报告是对外承担法律责任的文件。当前原始记录手写归档、报告人工誊抄，一旦遇到客户争议、监管抽查、产品召回追溯，企业**无法证明这份数据从录入到出报告从未被改动**；举证不能，即在法律上处于被动甚至面临败诉风险。
- **数据资产流失风险.** 核心检测数据散落于纸面与个人电脑，离职、误删、损毁即永久丢失；而普通数据库中的数据**可被任何拥有权限者静默修改且不留痕迹**，等同于无保险的资产。
- **无法自证清白.** 依赖人工核对 + 普通数据库，既不能阻止内部篡改，也无法在事后向第三方（客户、审计、监管）**证明数据完整性**。合规审计时只能被动接受质疑。
- **无法规模化、无法智能化.** 数据非结构化，业务量一涨文员即成瓶颈，且无从接入任何智能审核与历史数据分析。

### SRDF 标准确立的价值（管理层视角）

| 维度 | 传统方式 | SRDF 标准 |
|---|---|---|
| **数据防伪** | 可被静默修改、无痕 | 每次改动进入**密码学哈希链**，改一个字、换一张照片都留下不可抹除、可检出的痕迹 |
| **可追溯/自证** | 查阅纸质档案，举证困难 | 任意历史报告凭版本三元组**精确重建、逐位复现**，自证清白由不可能变为可随时验证 |
| **合规护城河** | 依赖通用格式/外部厂商 | 数据资产以**企业自主标准**固化，不受任何外部格式或供应商挟持，形成难以复制的合规壁垒 |
| **降本增效** | 手抄手算、人力线性增长 | 一次录入、自动出报告，业务量与人力**脱钩** |
| **AI 就绪** | 数据封闭于 Word/纸面，AI 难以读取与利用 | 数据是带语义的形式对象，**AI 智能体可自动审核、校对、填充、梳理版本、提建议**；且受形式护栏约束：AI 仅提议、不作终裁，定版必由人工签署，经 AI 处理的每一字段永久可查 |

> **战略定位.** SRDF 不是一个生成报告的软件，而是一道**面向合规与法律风险的数据资产防火墙**。它把数据从未被改动这一原本无法验证的承诺，变成一项可向客户、审计、监管出示的**数据防伪证明**。

---

> **摘要.** 本规范定义一种面向化学检测领域、与现有任何文档格式（含 OpenDocument、OOXML、PDF 源格式、Typst、LaTeX 等）**均不兼容**的自主可控结构化文档标准 SRDF。SRDF 在结构上由**九层核心栈**（抽象模型→语法→模式→语义→求值→约束→生命周期→绑定→呈现→归档）与**四大横切平面**（本体平面 Ω、协同平面 Σ、出处平面 Π、智能体平面 Α）正交组成。规范以**树自动机**刻画模式校验、以**类型系统 + 抽象解释**刻画静态语义、以**一阶逻辑**刻画完整性约束、以**关系视图与双向镜头**刻画原始记录到报告的映射、以**Petri 网与模态/时序/道义逻辑**刻画审签生命周期、以**初始代数上的同态（catamorphism）**刻画后端无关的排版指称语义、以**描述逻辑本体**刻画领域语义、以**无冲突复制数据类型（CRDT）**刻画多人协同与版本演化、以**Merkle 出处账本**刻画防篡改与长期可复现、以**受形式护栏约束的智能体提案**刻画 AI 友好的填充/审阅/校对/版本管理/建议能力。本规范的呈现语义是后端无关的：符合性实现可自由选择满足规范语义的排版内核。

## 1. 范围、目标与自主可控性论证

### 1.1 范围 [N]

本规范规定化学检测领域**原始记录文档**与**检测报告文档**的统一抽象模型、序列化语法、约束体系、求值语义、协同演化、出处保全与符合性要求。本规范不规定可视化编辑器的人机交互实现，亦不规定底层排版内核的具体实现。

### 1.2 设计目标与对应业务需求 [N]

SRDF 的设计目标 **D1–D11** 直接对应化学部的真实业务需求（详尽对照）：

| 目标 | 内容 | 对应业务需求 |
|---|---|---|
| **D1** 数据—约束—样式三元正交 | 三维互不经实例传播 | 标准/客户变更只改一处 |
| **D2** 结构化可计算 | 字段携类型、单位、角色 | **人工录入**可静态校验 |
| **D3** 可形式验证 | 约束=一阶逻辑、生命周期=模态/时序 | 法律文件正确性 |
| **D4** 呈现确定性 | 同输入逐位元同输出 | **自动出 PDF**、长期可复现 |
| **D5** 后端无关 | 抽象呈现语义独立于引擎 | 自主可控、可换内核 |
| **D6** 零代码可达 | 全操作可结构化表达 | 工程师/文员不写代码 |
| **D7** 协同收敛 | 多副本强最终一致 | **将来多人协作** |
| **D8** 版本可演化 | 版本构成半格、可合并 | **版本控制** |
| **D9** 出处不可篡改 | 内容寻址 + 哈希链 | **防篡改**、可审计 |
| **D10** 自动实例化 | 数据按模板自动、确定、全有或全无地填充 | **自动填充、节省人工** |
| **D11** 智能体可操作 | 文档为形式对象，AI 可填充/审阅/校对/管理版本/提建议，受形式护栏约束 | **AI 智能审核与节省人工**（Α 平面） |

### 1.3 与既有标准的关系 [N]

本规范**不规范性引用、不兼容、不复用**任何既有文档格式族。SRDF 禁止与 OpenDocument（ISO/IEC 26300）、OOXML（ISO/IEC 29500）在命名空间、元素语义、打包结构上兼容；其模式语言 SRSL **不是、也不兼容** XSD/RELAX NG（自定义树自动机语义）。OpenDocument 仅作反向资料性参照。

> **自主可控性论证 [I].** 自主可控的充分条件不是自造渲染器，而是**对格式语义拥有完全的形式化定义权与演化权**。SRDF 把规范主体定义在抽象语义层，把排版内核降格为可插拔后端，并以出处平面保证文档资产的长期自持。三者构成自主可控的形式化充分条件。

## 2. 体系结构：九层核心栈 + 四横切平面 [N]

SRDF 在结构上是**核心栈 × 横切平面**的正交积。核心栈自底向上九层、层间单向归约；四个横切平面与栈正交，分别注入领域语义、协同语义、出处语义与智能体语义。

**核心栈（自顶向下，层间单向归约 `L_{i+1} ⇊ Lᵢ`）：**

| 层 | 名称 | 核心机制 |
|---|---|---|
| L9 | 归档 | PDF/A、确定性、出处锚 |
| L8 | 呈现 | 布局代数、catamorphism |
| L7 | 绑定 | 关系视图 + 双向镜头 |
| L6 | 生命周期 | Kripke + Petri + 道义逻辑 |
| L5 | 约束 | 一阶逻辑 |
| L4 | 求值 | SRFL 操作语义 |
| L3 | 语义 | 类型系统 + 抽象解释 |
| L2 | 模式 | SRSL = 树自动机 |
| L1 | 语法 | SRML（XML 序列化） |
| L0 | 抽象模型 | SRDM |

**四横切平面（与核心栈正交注入 `⟂`）：**

| 平面 | 名称 | 注入内容 | 主要作用于 |
|---|---|---|---|
| Ω | 本体平面 | 描述逻辑领域本体 | L0 / L3 / L5 |
| Σ | 协同平面 | CRDT 多副本收敛、版本半格 | L0–L7（可变层） |
| Π | 出处平面 | Merkle 出处账本、防篡改、版本锚 | L6 / L9 |
| Α | 智能体平面 | AI 智能体受护栏约束的提案能力 | L5 / L6 / L7 / Π |

**层间一致性公理 [N].** 相邻层存在归约全函数 `lowerᵢ` 且保持合法性：

```
 Valid_{i+1}(x)
 ───────────────────────────── (LOWER-PRESERVE)
 Valid_i( lower_i(x) )
```

**平面正交公理 [N].** 每个横切平面 `Π/Σ/Ω/Α` 经由**投影**作用于栈，但不改变栈内层间归约：核心栈语义在抹去平面注入后仍封闭。该正交性是 D1（三元正交）的体系结构落实。

## 3. 抽象文档模型 SRDM [N]

SRDM 是语义中枢，文档为带类型标注的有序树，以代数数据类型给出：

```
Document ::= Doc(meta : Meta, page : PageModel, body : Section*)
Meta ::= M(entries : (Key×Val)*, prov : Provenance, state : LifeState)
Section ::= Sec(id : NodeId, role : SectionRole, children : Node*)
Node ::= NField(Field) | NTable(Table) | NImage(ImageSlot)
 | NGroup(Group) | NComputed(Computed)
Field ::= Fld(id, name : Name, ty : Type, card : Card,
 role : FieldRole, value : Value?)
Table ::= Tbl(id, schema : RowSchema, rows : Row*, aggregates : Aggregate*)
RowSchema ::= Σ(cols : (Name × Type)*)
Computed ::= Cmp(id, ty : Type, expr : SRFL)
ImageSlot ::= Img(id, ref : BlobRef, cap : Text?) (* *)
Value ::= VText(String) | VNum(Decimal, Unit) | VDate(ISO8601)
 | VBool(𝔹) | VEnum(Symbol) | VImg(BlobRef) | VNull
BlobRef ::= cid( H(bytes) ) (* 内容寻址标识 *)
Card ::= One | Opt | Many(min : ℕ, max : ℕ∪{∞})

(* ── 页面装订模型 PageModel：页眉/页脚为一等公民 ── *)
PageModel ::= PM(size : PageSize, margins : Margins, furniture : Furniture*)
Furniture ::= Furn(slot : Slot, scope : PageScope, zones : Zone*)
Slot ::= Header | Footer
PageScope ::= AllPages | FirstOnly | ExceptFirst | OddPages | EvenPages
Zone ::= Z(pos : ZonePos, runs : RunNode*) (* 三分区版面 *)
ZonePos ::= ZLeft | ZCenter | ZRight
RunNode ::= RText(String) (* 静态文本 *)
 | RField(NodeId) (* 绑定字段：报告编号/客户名 *)
 | RVar(PageVar) (* 页面变量，见下 *)
 | RImage(BlobRef) (* 抬头 logo / 资质章 / 骑缝章 *)
 | RRule(Width) (* 页眉/页脚分隔线 *)
PageVar ::= PageNo | PageCount | DocId | DocVersion
 | SectionTitle | IssueDate | Classification (* 密级标识 *)
```

**记号.** 文档论域 `𝒟`，节点全集 `nodes : 𝒟 → 𝒫(𝒩)`，字段子集 `fields(d) ⊆ nodes(d)`。页面装订注入排版框 `frame(·,·,·)`，其视觉样式（字体、线宽、抬头位）由公司级样式包 `Θ`集中规定，文档实例仅提供**内容与版面位**，不得覆写非授权样式槽（D1 正交）。

> **设计依据 [I]（页眉页脚为何升为一等公民，且为何要页码 X/共 Y 页与密级/资质位）.** 检测报告是**受控的法律文件**，其页眉页脚承载的不是装饰，而是合规要素：(a) **报告编号、版本号、密级标识**须逐页出现，便于受控管理与防混淆；(b) **CNAS/CMA 等资质章、公司抬头 logo、骑缝/资质印**以 `RImage(BlobRef)` 内容寻址插入，享防换图保护；(c) **第 X 页 / 共 Y 页**（`PageNo`/`PageCount`）是法律文件**防抽页/防漏页**的人工可读防线：任何人抽去中间一页，页码与总页数立即暴露，与密码学防篡改形成人工核验 + 机器校验的双重保险。把这些建为模型一等公民（而非置于不透明的 Meta），才能对其做结构化校验、绑定与确定性渲染。`PageScope` 区分首页/奇偶页，是因为报告**首页常用完整抬头、后续页用简版**，奇偶页页眉镜像，属印刷级硬要求。

> **设计依据 [I]（图片为何用内容寻址 BlobRef，而非内联）.** 化学部报告含大量实验室照片与设备截图，且**同一张原样照片常被多份报告引用**。`BlobRef = cid(H(bytes))` 将图片以**内容寻址**方式外置：(a) 相同图片哈希相同，天然**去重**，省存储；(b) 图片字节一旦变化哈希即变，**任何静默替换都会断链**（防篡改）；(c) 文档树只持有定长哈希，使 SRDM 保持轻量、可快速差分比对与合并（协同）。这是插入图片这一需求在模型层的根因设计。

## 4. 具体语法 SRML（XML 序列化）[N]

SRML 是 SRDM 的具体序列化，命名空间 `urn:q-chem-doc:srdf:1.0`（禁止复用既有命名空间）。文法节选。

**良构性 [N]**（纯语法）：XML 1.0 良构、单根、`id` 唯一、`typeRef` 可解析。
**往返律 [N]**：存在 `parse : SRML ⇀ 𝒟` 与 `print : 𝒟 → SRML`，满足 `print(parse(s)) ≅ s` 与 `parse(print(d)) = d`。

## 5. 模式与约束语言 SRSL：树自动机语义 [N]

SRSL 是 SRDF 自有模式语言，**不兼容 XSD/RELAX NG**。其有效性判定的形式基础是**无序树自动机**。

### 5.1 SRDM 树作为无秩树

SRDM 是**无秩有序树**（节点子序列宽度无界，如表格行数、分项目数不定）。定义自底向上无序树自动机：

```
𝒜 = ⟨Q, Λ, Δ, F⟩
 Q : 状态有限集（每状态对应一类合法子结构）
 Λ : 节点标号集（field / table / section / image / …）
 F ⊆ Q : 接受状态
 Δ : 转移规则，形如 a( L ) → q
 其中 a ∈ Λ，L ⊆ Q* 为子状态序列的水平语言，由正则串自动机识别
```

**运行与接受 [N].** 自底向上对每个节点 `n`（标号 `a`、子节点状态序列 `w ∈ Q*`）赋状态 `q`，当且仅当 `∃ (a(L)→q) ∈ Δ. w ∈ L`。文档有效当且仅当根节点状态 `∈ F`：

```
 run_𝒜(root(d)) = q q ∈ F
 ────────────────────────────── (TA-ACCEPT)
 d ⊨ S_𝒜
```

完整有效性叠加一阶层：`valid_S(d) ⟺ d ⊨ S_𝒜 ∧ 𝔄(d) ⊨ Φ_FOL`。

> **设计依据 [I]（复杂表格为何用树自动机，而非平铺记录类型）.** 化学检测原始记录普遍是**多行多列、含汇总行、可嵌入子表与图片的数据矩阵**，其子结构宽度不定、可递归嵌套。平铺的固定字段记录无法描述这种**无界宽度 + 嵌套**结构；而无序树自动机的水平语言由正则串自动机识别恰好刻画一个表格可有任意多行、每行须匹配列模式。把模式校验定义为树自动机接受性，使**复杂表格的合法性判定既可判定、又线性可算**，是复杂表格需求在 L2 的根因设计。

## 6. 静态语义：类型系统 + 抽象解释 [N]

### 6.1 类型论域与子类型

```
Type τ ::= Text | Num⟨u⟩ | Date | Bool | Enum⟨S⟩ | Image | Table⟨Σ⟩ | Opt⟨τ⟩
```

`u ∈ Unit` 取自单位代数（自由阿贝尔群，基为 SI 量纲）。子类型偏序 `⊑` 关键规则：

```
 u ≡_dim u' τ ⊑ τ'
 ───────────────────── (S-NUM) ───────────────── (S-OPT)
 Num⟨u⟩ ⊑ Num⟨u'⟩ τ ⊑ Opt⟨τ'⟩
```

类型构成带 `⊥/⊤` 的有限格 `⟨Type, ⊑, ⊔, ⊓⟩`。类型判断 `Γ ⊢ e : τ`；满足进展性与保持性。

### 6.2 值域抽象解释与精化类型

人工录入的字段值需在**编译期**做范围/单位健全性检查。为此定义具体域与抽象域：

```
具体域 𝒞 = 𝒫(Value) （某字段所有可能取值的集合）
抽象域 𝒜 = Type × Unit × Interval （类型 × 单位 × 数值区间）
```

二者经 **Galois 连接** `(α, γ)` 相连，`α : 𝒞 → 𝒜`、`γ : 𝒜 → 𝒞`，满足 `α(c) ⊑ a ⟺ c ⊆ γ(a)`。字段的**精化类型**记 `{ x : Num⟨u⟩ | ℓ ≤ x ≤ h }`，其抽象语义即区间 `[ℓ,h]`。静态检查是抽象域上对依赖图的**单调不动点**计算：

```
 â = lfp( λX. F♯(X) ) α(录入值) ⋢ â（落在声明区间外）
 ─────────────────────────────────────────────────────────── (AI-REJECT)
 编译期拒绝，禁止下沉至报告
```

> **设计依据 [I]（人工录入为何要抽象解释 + 精化类型）.** 数据由实验室人员**手工录入**，是误差与越界的主要来源（如透光率应 ∈ [0,100]%、维卡软化温度量纲必须为温度）。抽象解释提供**可靠的过近似**：在数据进入法律报告之前，于编译期对区间 + 单位做静态判定并**就地拦截**越界/错单位录入，把手抄手算误差消灭在源头。精化类型让这些业务阈值成为类型的一部分，而用户从不书写它们（D6，由编辑器结构化生成）。

## 7. 完整性约束：一阶逻辑层 [N]

每个文档解释为一阶结构 `𝔄(d)`，论域为节点∪值∪类型，含谓词 `Field/Required/Defined/Binds/SameDim/ReportCell/…`。规范性完整性公理集 `Φ₀`（节选）：

```
C1 标识唯一: ∀x∀y. ( id(x)=id(y) → x=y )
C2 必填完备: ∀f. ( Field(f) ∧ Required(f) → Defined(valueOf(f)) )
C3 绑定存在: ∀c. ( ReportCell(c) → ∃s. Binds(c,s) )
C4 绑定唯一: ∀c. ( ReportCell(c) → ∃!s. Binds(c,s) )
C5 量纲相容: ∀c∀s. ( Binds(c,s) → SameDim(typeOf(c), typeOf(s)) )
C6 聚合封闭: ∀a∀t. ( Aggregate(a,t) → ∀r(InRow(r,t) → DefinedCol(r,keyOf(a))) )
C7 结论可达: ∀k. ( ConclusionItem(k) → ∃p. DerivesFrom(k,p) )
```

**可判定性 [N].** 论域有限，`Φ₀ ∪ Φ_user` 落在 Bernays–Schönfinkel 片段，可满足性可判定且多项式可算；符合性实现必须在编译期语义分析相（相④）完全求解，禁止把违例推迟到呈现期。

## 8. 公式语言 SRFL 与求值语义 [N]

SRFL 是计算派生值的纯函数表达式语言，用户永不书写其源文本（D6）。语法、小步操作语义 `⟨e,σ⟩ ⇝ ⟨e',σ⟩`（E-REF/E-AVG/E-ADD/E-CONV/E-IF）。

**合流性（Church–Rosser）[N]** 与 **强正规化 [N]**：SRFL 纯函数、无递归无界循环，任意求值次序得同一范式且必停机，这是 D4 确定性与编译期全量预求值的基础。

## 9. 数据绑定 SRBL：关系视图 + 双向镜头 [N]

绑定层把原始记录→报告既刻画为**关系视图**（语义），又刻画为**双向镜头**（可逆性与编辑回写）。

### 9.1 报告即关系视图

把原始记录的字段/表格视为**关系**，报告则是其上的一个**关系代数视图**：

```
Report = π_{报告列}( σ_{筛选}( RawRecord )) ⋈ Equipment ⋈ Sample
ConclusionTable = γ_agg[ key, fn ]( ProjectResults ) (* 分组聚合 *)
```

设原始记录关系模式上的**函数依赖集** `Ξ`。规范要求原始记录模式满足 **BCNF**：对每个非平凡依赖 `X → Y ∈ Ξ⁺`，`X` 必为超键。

> **设计依据 [I]（版本控制与数据只录一遍为何要关系视图 + BCNF）.** 旧流程最大的浪费是同一份数据需在原始记录与报告中重复录入两遍以上。把报告定义为原始记录上的**视图**，意味着数据**只在原始记录录入一次**，报告各单元格由视图自动派生，从而消除二次誊抄。要求原始记录模式 **BCNF**，则保证无传递/部分依赖、**无冗余存储**，从根本上杜绝同一事实多处存储、改一处而漏改他处的版本不一致。这是数据一次录入、全程结构化承诺的形式化。

### 9.2 绑定即双向镜头（实现业务零代码编辑、削减外包配置成本的基石）

报告单元格的取值位点与原始记录之间，以及**编辑器视图与 SRDM 之间**，建立**良行为非对称镜头**`ℓ = (get, put)`：

```
get : Source → View
put : Source × View → Source
满足: put(s, get(s)) = s (GetPut，恒等编辑不扰动源)
 get(put(s, v)) = v (PutGet，回写后再读得回写值)
```

绑定 `β : Sink(d_rep) ⇀ Source(d_src)` 须满足类型与量纲相容（C5）。良定义性定理：

```
 valid(d_src) valid(d_rep) β 全覆盖 Sink(d_rep)（C3） β 唯一（C4） 类型相容（C5）
 ───────────────────────────────────────────────────────────────────────────────────── (BIND-WD)
 实例化 inst(d_rep,β,d_src)=eval∘subst_β(d_rep) 存在且唯一
```

> **设计依据 [I]（零代码编辑与人工修正为何要镜头律）.** (1) 可视化编辑器对用户呈现的是**视图**，真值来源是 SRDM；`get/put` 律保证用户在视图上的无操作绝不静默改动底层模型（GetPut），使所见即所修、模型可控（支撑 D6 零代码）。(2) 个别报告值允许工程师**人工修正**：镜头的 PutGet 律精确规定回写必须一致，而对**只读派生单元格**（如自动汇总结论）则将其镜头设为 `put` 不可用，从机制上**禁止下游篡改上游**。将映射构造为镜头，使自动派生与受控人工修正在同一形式框架内共存。 |

### 9.3 自动实例化：把实验数据按合规模板自动填充（D10）[N]

本节形式化软件自动将实验员录入的数据按合规模板实例化为报告、免去人工誊抄这一核心自动化能力。它是关系视图与绑定的运行化。

#### 9.3.1 自动填充函数

给定**已冻结并版本化的绑定** `β`（一次性配置、亦可进一步自动推断），自动填充是一个**全函数**：

```
autofill_β : Template × DataRecord ⇀ Report
autofill_β(d_rep, d_src) ≜ inst(d_rep, β, d_src) = eval ∘ subst_β (d_rep)
```

其**良定义性、唯一性**由 BIND-WD 保证；其**确定性**（同数据 ⇒ 同报告）由合流 + catamorphism 唯一性保证。即：**一次配好 `β`，此后每来一份合规录入数据 `d_src`，系统自动产出唯一确定的报告，零人工誊抄。**

#### 9.3.2 语义自动绑定（连一次性的映射配置也尽量免除）[N]

绑定 `β` 本身可借**本体平面 Ω**自动推断候选：当报告位点 `c` 与原始记录源 `s` 标注同一/可包含的领域概念且量纲相容时，系统自动生成候选绑定，由人**仅做确认**而非从零点选：

```
 typeOf(c)=Concept<C> typeOf(s)=Concept<C'> 𝒯 ⊨ C' ⊑_DL C SameDim(c,s)
 ───────────────────────────────────────────────────────────────────────────── (AUTO-BIND)
 (c ↦ s) ∈ β_candidate
```

`β_candidate` 经人工确认后冻结为 `β` 并锚入出处账本。这把文员逐格点选压缩为审核系统建议。

#### 9.3.3 全有或全无的安全闸（法律文件不容半填）[N]

自动填充**禁止产出半成品报告**。实例化前必须通过准入校验，否则**整体拒绝**并报告缺口，绝不输出部分填充的报告：

```
 ¬( β 全覆盖 Sink(d_rep) ∧ 类型/量纲相容 ∧ valid(d_src) )
 ────────────────────────────────────────────────────────────── (FILL-OR-REFUSE)
 autofill 拒绝并返回未满足位点集，禁止生成任何 PDF
```

#### 9.3.4 批量与触发 [N]

自动填充是**纯函数**，故可安全并行批处理：对一批录入数据 `{d_src⁽ᵏ⁾}`，`map(autofill_β, ·)` 各自独立、可并发、结果确定。生命周期中实验数据提交（数据版本封版）事件**可触发**自动填充流水线（相⑥⑦⑧⑨），实现录入完成 → 报告自动就绪。

> **设计依据 [I]（自动填充为何既能节省人工又不引入法律风险）.** 软件自动按合规模板填充数据、节省大量人工，在本标准中并非新机制，而是关系视图 + 绑定的**直接运行化**：绑定 `β` 一次性配置完成（亦可借本体自动推断，将该配置也降至最小），之后 `autofill_β` 对每份录入数据**自动、确定、唯一**地产出报告，彻底替代手工誊抄。关键在三条护栏：(a) **确定性**：同数据必得同报告，可复算、可审计；(b) **全有或全无**（FILL-OR-REFUSE）：绝不产出漏填关键值却照常生成 PDF 的半成品法律文件，缺数据时明确报告缺口而非含糊放行；(c) **出处留痕**：每次自动填充记录所用的模板版本、数据版本、绑定版本（三元组），自动化产出与手工产出享同等可追溯性。在节省人工的同时，不使必要的人工把关沦为无人把关。 |

## 10. 生命周期：Kripke + Petri 网 + 模态/时序/道义逻辑 + 精化 [N]

报告为法律文件，其状态迁移、并发审签、不可篡改性须形式化。本层用三套互补模型刻画。

### 10.1 Kripke 模型与时序/道义公理

```
ℳ = ⟨W, R, V⟩, W = {Draft, InReview, Signed, Archived, Revoked}
```

LTL/道义公理（节选，`G` 恒真、`U` 直到、`O` 义务、`F`(道义)禁止）：

```
LC1 单调归档: G( Archived → G Archived )
LC2 不可篡改: G( Archived → G ¬Editable )
LC3 签前可改: G( ¬Signed → Editable )
LC4 评审前置: ¬Reviewed U Signed 为不可满足
SG1 工程师义务: InReview → O( Sign_engineer )
SG2 顺序义务: F( Sign_clerk ∧ ¬Sign_engineer ) (* 禁止文员先于工程师签 *)
```

### 10.2 审签工作流的 Petri 网模型与健全性

多角色（客服/工程师/文员/系统）可**并发**推进多份报告，故以**工作流 Petri 网** `N = ⟨P, T, F, m₀⟩` 建模：库所 `P` 含文档状态与角色令牌，变迁 `T = {submit, review, sign_eng, sign_clerk, archive, revoke}`。要求 `N` 满足 **van der Aalst 健全性**：

```
S1 可终结性: ∀m( m₀ →* m ⟹ m →* m_final ) (* 任一已派单报告终能归档 *)
S2 正常终结: m_final 是唯一可达终标识，且终结时无残留令牌
S3 无死变迁: ∀t∈T. ∃m. ( m₀ →* m ∧ m 使能 t ) (* 无永不触发的环节 *)
```

> **设计依据 [I]（将来多人协作为何先上 Petri 网 + 健全性）.** 化学部业务量上涨后，工程师录数据、文员配映射、系统出报告将**并发进行**，且一名工程师可同时处理多份委托。Petri 网天然刻画**并发与资源（令牌）竞争**；健全性 S1–S3 在设计期即**静态证明**：无论并发交错如何，(a) 每份已派单报告终能归档（无活锁）、(b) 流程无残留/无死环节。即使首版只单人使用，模型已为多人协作预留正确性保证，**上线后无需重构流程语义**。 |

### 10.3 实现作为规范的精化

实现的迁移系统 `𝒯_impl` 必须**精化**抽象规范 `𝒯_spec`，以**弱互模拟** `≈` 见证：`𝒯_impl ≈ 𝒯_spec`。LC/SG/S 公理由**模型检验**（LTL/CTL，可用 TLA+ 规约）对状态空间**全路径**验证，而非仅测试抽样。

> **设计依据 [I]（防篡改为何要模型检验而非测试）.** 归档后不可篡改（LC2）是法律承诺，**测试只能覆盖有限路径**，无法证明不存在某条迁移序列绕过不可变性。模型检验对状态机**穷尽所有路径**验证 LC2/SG2，给出任何执行下都成立的强保证；弱互模拟则保证真实实现与抽象规范行为一致，使该保证从规范传递到实现。 |

## 11. 排版语义：布局代数 SRLA + 初始代数同态（catamorphism）[N]

### 11.1 后端无关原则（不可侵犯的根本原则）[N]

> ## **【根本原则 P0｜后端无关】**
>
> **本规范定义的是语义，而非实现。** SRDF 规定文档必须意味着什么（抽象呈现语义 `⟦·⟧ : 𝒟 → Page*`），**绝不规定、绝不限定**任何具体技术选型：存储采用何种数据库、界面采用何种框架、排版采用何种引擎，**全部属于实现自由度**。
>
> **判定一个实现是否合规的唯一标准**，是它能否证明满足语义保持义务 `α ∘ ℐ = ⟦·⟧`，以及形式正确性，**而非其采用了何种技术**。
>
> **推论（规范性）：** 任何关于该用 A 数据库还是 B 数据库、该用 A 前端还是 B 前端、能否复用某现成引擎的争论，**在本标准层面均无意义、不予讨论**。标准不剥夺实现者的任何技术自由；作为对价，实现者**必须对法务级的绝对正确性独立负责**。

定义**抽象**呈现语义 `⟦·⟧ : 𝒟 → Page*`，不绑定任何排版引擎。符合性实现可自由选择满足 `⟦·⟧` 的后端（语义保持义务）。此即 D5 与自主可控的形式核心，也是标准 ≠ 设计文档的分界线。

### 11.2 布局代数 SRLA（盒代数）

```
Box b ::= glyph(c) | hbox(b*) | vbox(b*) | grid(b**) | glue(nat,str,shr)
 | penalty(p) | rule(w) | frame(hdr,b,ftr)
```

`(Box, ⊕, hbox[])` 与 `(Box, ⊗, vbox[])` 各为幺半群。

### 11.3 SRDM 为初始 F-代数，⟦·⟧ 为唯一 catamorphism

设函子 `F` 刻画 SRDM 的一层结构（`F X = Meta × (SecF X)*`，其中 `SecF X` 描述节点的一层展开）。则 SRDM 是 `F` 的**初始代数** `(μF, in)`。给定**载体为盒代数的 F-代数** `(Box, φ)`（`φ` 把已渲染的子盒装配为父盒），存在**唯一同态**，即 catamorphism `⦇φ⦈ : μF → Box`，满足以下同态方程（即范畴论中初始代数图表的交换条件）：

```
 ⦇φ⦈ ∘ in = φ ∘ F⦇φ⦈ (CATA，⦇φ⦈ 由该方程唯一确定)
 ⟦·⟧ ≜ paginate ∘ ⦇φ⦈ （φ 取自公司级样式包 Θ）
```

其中 `in : F(μF) → μF` 为初始代数的构造子、`F⦇φ⦈ : F(μF) → F(Box)` 为函子对 `⦇φ⦈` 的提升。方程 CATA 在 `(μF,in)` 为初始代数时**有且仅有一个解 `⦇φ⦈`**，这正是渲染含义唯一性的代数来源。

代表性装配方程：

```
⦇φ⦈( Tbl(_,Σ,rs,ag) ) = grid([header Σ] ++ map(⦇φ⦈, rs) ++ map(⦇φ⦈, ag))
⦇φ⦈( Sec(_,r,cs) ) = styled(r, ⊗ⱼ ⦇φ⦈(cⱼ))
⦇φ⦈( Cmp(_,τ,e) ) = render(τ, normalform(e)) （先 求值至范式）
```

> **设计依据 [I]（自动出 PDF + 任意嵌套复杂表格为何用 catamorphism）.** 报告含**任意深度嵌套**的分区/分组/子表/图片，且要求**自动、确定性**地生成。将渲染定义为初始代数上的 catamorphism，带来两条硬性质：(a) **唯一性**：初始代数到任何 F-代数的同态唯一，意味着一份文档恰有一个渲染含义，这正是 D4 确定性的代数根（确定性定理）；(b) **组合性**：`grid` 装配子盒的方式与嵌套深度无关，故**任意复杂的嵌套表格/分区都按同一自底向上规则合成**，无需为每种嵌套编写特例。自动出 PDF 与复杂表格两个需求在 L8 由同一条同态律统一支撑。 |

### 11.4 实现的语义保持义务 [N]

后端 `ℐ : 𝒟 → PDF` 符合本规范，当且仅当存在抽象化 `α : PDF → Page*` 使 `α ∘ ℐ = ⟦·⟧`。该等式把更换后端的正确性化为可校验等式，从而允许内部以高性能排版内核充当 `ℐ` 而不损标准权威性。

### 11.5 公司级样式包 Θ [N]

`Θ` 是与文档实例正交（D1）的全局样式环境（字体、字号阶、行距、表线阶、页眉页脚、签字位坐标），集中维护、单点变更全局生效，并作为 catamorphism 的代数 `φ` 注入。

### 11.6 页眉页脚的注入与页码不动点 [N]

 的页面装订模型 `PageModel` 在排版期经分页函数注入每一页的 `frame(hdr, body, ftr)`。对第 `i` 页（共 `n` 页），其装订盒由如下函数装配（`scopeMatch` 按 `PageScope` 选取首页/奇偶页版本，`runbox` 渲染分区运行内容）：

```
furnishᵢ(d, i, n) = frame( hdr = renderSlot(Header, i, n),
 body = pageBodyᵢ,
 ftr = renderSlot(Footer, i, n) )

renderSlot(slot,i,n) = hbox[ runbox(ZLeft,i,n) , glue , runbox(ZCenter,i,n) ,
 glue , runbox(ZRight,i,n) ]

⟦RVar(PageNo)⟧ = i ⟦RVar(PageCount)⟧ = n ⟦RField(x)⟧ = valueOf(x)
```

**页码不动点 [N].** 页脚含 `PageCount`（共 Y 页）时存在自指：总页数 `n` 取决于分页结果，而注入共 n 页本身又可能改变行高、触发再分页、改变 `n`。故 `paginate` 必须求解**不动点**

```
 n* = lfp( λn. |paginate( furnish(d, ·, n) )| )
 ────────────────────────────────────────────────── (PAGE-FIXPOINT)
 采用 n* 注入所有页的 PageCount
```

由于页数单调有界（页内容有限），该迭代必收敛；规范要求实现迭代至 `nₖ₊₁ = nₖ` 稳定后方可定版。**收敛即唯一**，故页码注入不破坏确定性定理（PAGE-FIXPOINT 的最小不动点唯一）。

> **设计依据 [I]（共 Y 页为何必须是不动点而非简单计数）.** 正确标定第 X 页 / 共 Y 页，是法律文件防抽页的前提：但 `Y` 一旦印入页脚，就可能多占一行、将末页内容挤入新一页，使 `Y` 自增，朴素的先计数再填充会得到错误的总页数。规范以最小不动点 PAGE-FIXPOINT 精确定义其语义并证明收敛与唯一，使所有合规后端对同一文档算出**同一个 Y**，把一个看似琐碎、实则极易出错的印刷细节确立为确定性可验证的语义，这正是标准而非设计文档的价值所在。

## 12. 编译流水线 [N]

从 SRML 源到 PDF/A 的全链路为九相顺序流水线，各相依次归约（前一相输出为后一相输入）：

| 相 | 名称 | 输入 → 输出 | 依据 |
|---|---|---|---|
| ① | 词法分析 | SRML 源 → Token 流 | |
| ② | 语法分析 | Token 流 → SRDM(AST) | 往返律 |
| ③ | 名字解析与符号表 | AST → 带作用域 AST | C1 唯一性 |
| ④ | 语义分析 | 静态验证（含 a–e 五项）；任一失败⇒编译期报错、禁止下沉 | |
| ⑤ | IR 生成 | AST → IR（L8→…→L1 归约） | |
| ⑥ | 绑定与实例化 | IR → 实例化 IR（`subst_β`、关系视图物化） | |
| ⑦ | 公式预求值 | → 常量折叠后 IR（`eval` 至范式） | |
| ⑧ | 布局求解 | → 分页盒模型（`⦇φ⦈ ⇒ Box ⇒ paginate ⇒ Page*`） | |
| ⑨ | 后端代码生成 | Page* → PDF/A 字节流（可插拔 `ℐ`） | |

其中相④的语义分析须**完整**完成：a. 类型检查、b. 抽象解释/区间、c. 一阶约束求解、d. 依赖图无环、e. 生命周期模型检验；任一项失败即报错，禁止下沉（LOWER-PRESERVE）。

**相④必须完全完成全部静态验证**；**相⑨后端为实现自由度**，任何满足语义保持义务与归档约束的内核均合规，可插拔后端是自主可控的运行时体现。

## 13. 符合性等级 [N]

| 等级 | 必满足 | 适用 |
|---|---|---|
| **SRDF-A** | 核心栈 L0–L9 + 四平面 Ω/Σ/Π/Α 全部，含模型检验与语义保持 | 生产报告生成 |
| **SRDF-B** | L0–L8 + Σ 协同， 降为运行期校验 | 协同编辑/预览 |
| **SRDF-C** | L0–L5 + Ω 本体（结构 + 约束，不含求值与呈现） | 数据交换/校验 |

声明等级的实现必须通过配套一致性测试套件（CTS）对应子集。

### 13.1 分期实施路线图（资料性）[I]

SRDF-A 是宏大的目标态，全量落实周期长。为**敏捷响应业务、尽早交付价值**，建议分三期推进。**关键约束：一期即须交付合规承诺的核心要件，不得为求快而将其省去。**

| 期 | 目标符合性 | 落实内容 | 可用通用技术栈 |
|---|---|---|---|
| **一期（MVP）** | **SRDF-C⁺ ＝ SRDF-C ＋ 出处平面 Π** | 结构化建模、模式/约束校验、数据录入；**外加防篡改哈希链与版本三元组** | 关系型数据库 + 表单校验 + 仅追加审计表 |
| **二期** | SRDF-B | 公式求值、绑定映射、PDF 自动渲染、协同编辑（Σ） | 在一期之上叠加渲染后端与协同层 |
| **三期** | SRDF-A | 生命周期模型检验、全量语义保持验证 | 形式验证工具链补全 |

> **一期为何是 SRDF-C 而非 SRDF-A [I].** SRDF-C 的结构 + 约束层可由**最通用、最成熟的技术栈（关系型数据库 + 表单校验）**快速落实，无需等待全套形式验证工具链就位，从而以最小工程量在名义上启动标准、在事实上先支撑业务运转。这是宏大标准、敏捷启动的合理工程节奏。

> ⚠️ **一期为何必须是 C⁺ 而不是裸 C [I].** 标准原始定义的 SRDF-C **不含** 出处平面 Π（防篡改/出处账本）。但本规范对外（尤其是《商业与合规价值摘要》）承诺的核心卖点，正是**防篡改、可追溯、可自证**。**若一期交付裸 SRDF-C（只有关系库 + 表单校验、无哈希链），则交付物恰好缺失了对外承诺的那一项合规能力**：这会在合规审计、客户争议或追责时形成对外宣称防篡改、实际仅为普通数据库的实质落差，风险由实施方承担。所幸 Π 的一期实现成本极低（一张**仅追加的审计表 + 逐行哈希链 + 版本向量**即可，无需任何高级理论），故**强制并入一期**。即应用层体验可于二期迭代，但合规追溯内核必须在一期刚性交付。

## 14. 归档与合规 [N]

**确定性定理 [N].**

```
 StdVer 固定 ΘVer 固定 字体指纹固定 d ∈ 𝒟
 ────────────────────────────────────────────────────── (DETERMINISM)
 ⟦d⟧ 唯一，任一合规后端 ℐ 产出 bytes(ℐ(d)) 规范化后逐位元等同
```

证明纲要： 合流 + 强正规化（求值唯一）、 catamorphism 唯一性（布局唯一）、 语义保持（后端等同 `⟦·⟧`）复合即得。确定性是法律可复现性的形式保证。

## 15. 本体平面 Ω：领域描述逻辑 [N]

为给字段类型、单位与设备/样品/项目关系赋予**领域语义**，SRDF 引入一个**可判定的描述逻辑（DL）本体** `𝒪 = ⟨𝒯, 𝒜⟩`。

### 15.1 逻辑与论域

采用 `𝒜ℒ𝒞𝒬(D)`（带定性数量限定与具体域 `D` 的 `ALC`，可判定）。**TBox 𝒯**（概念公理）刻画领域术语：

```
TestItem ⊑ ⊤ （检测项目）
HeatDeflection ⊑ TestItem ⊓ ∃requiresUnit.Temperature
Equipment ⊑ ⊤ Sample ⊑ ⊤
TestItem ⊑ ∃usesEquipment.Equipment ⊓ ≤1 hasConclusion.Conclusion
Temperature ⊑ Quantity ⊓ ∃dim.{Θ} （具体域：温度量纲）
```

**ABox 𝒜** 为实例断言（某次检测、某台设备、某个样品）。

### 15.2 与核心栈的接口 [N]

字段类型可声明引用本体概念：`type="Concept<HeatDeflection>"`。其良型性附加包含判定：

```
 𝒯 ⊨ C ⊑_DL D valueOf(f) : Concept<C>
 ────────────────────────────────────────────────── (DL-TYPE)
 f 在要求 Concept<D> 处可用
```

包含判定 `⊑_DL`在 `𝒜ℒ𝒞𝒬(D)` 可判定（EXPTIME-complete，但本企业本体规模小、实际秒级）。

> **设计依据 [I]（人工录入的智能校验与将来 AI 审核为何要描述逻辑）.** (1) 录入期需要**领域级**校验：热变形温度项目必须配温度量纲、必须关联恰当设备，这类规则不是平铺类型所能表达的概念关系，DL 的 TBox 恰好刻画项目—设备—单位的本体约束，驱动编辑器给出**智能联动表单**。(2) 文档已写明的将来方向（接入 AI 智能审核、历史数据分析）需要机器**理解数据语义**而非仅存字符；DL 本体提供可推理的语义底座（概念包含、实例分类），是后续智能审核的形式入口。选可判定片段 `𝒜ℒ𝒞𝒬(D)` 而非全一阶，是为保证推理**必停机、可上线**。 |

## 16. 协同平面 Σ：CRDT 多人协同与版本演化 [N]

为支撑**将来多人协作**与**版本控制**，可变的 SRDM 不是普通树，而是一个**复合无冲突复制数据类型（CRDT）** `𝒞`，使多副本离线编辑后能**无冲突自动收敛**。

### 16.1 复合 CRDT 构造

SRDM 各构造按其语义选用对应 CRDT 原语：

```
文档树结构 : 可移动树 CRDT（带唯一 NodeId 与因果稳定的 move 操作）
有序子节点 / 表格行: RGA / 因果树序列 CRDT —— 保序、可并发插删
字段值 : MV-Register（多值寄存器）—— 并发写保留全部取值
集合型（如设备集）: OR-Set—— 并发增删可交换
计数/汇总缓存 : PN-Counter
```

每个副本维护**版本向量** `vv : ReplicaId → ℕ`。

### 16.2 收敛定理（强最终一致）[N]

CRDT 合并 `⊕ᶜ` 必须满足交换律、结合律、幂等律：

```
 a ⊕ᶜ b = b ⊕ᶜ a (a ⊕ᶜ b) ⊕ᶜ c = a ⊕ᶜ (b ⊕ᶜ c) a ⊕ᶜ a = a
 ───────────────────────────────────────────────────────────────────── (SEC)
 ∀ 副本，交付同一因果历史集 ⟹ 状态收敛至同一值
```

状态构成以 `⊕ᶜ` 为并的**联合半格**；版本向量偏序 `⊑_v` 给出因果序。

### 16.3 版本控制：版本即半格元素 [N]

每次提交产生一个不可变快照 `Vᵢ`，其版本标识为当时的版本向量；版本集 `(𝒱, ⊑_v, ⊔)` 为半格，三路合并 = 求 `⊔`（最近公共祖先经合并）。出报告时记录的数据版本即该版本向量，并锚入 Merkle 账本。

> **设计依据 [I]（多人协作为何选 CRDT 而非 OT，及对数据完整性的取舍）.** (1) **离线优先**：实验室录入常在**无网环境**（样品台、现场）进行，事后再同步。OT（操作变换）依赖中心服务器对操作做全局定序与变换，离线场景脆弱；CRDT 的合并**无需中心、可任意延迟**，离线编辑回到线上即自动收敛，契合实验室真实工况。(2) **设计先行**：将可变模型自第一版即建成 CRDT，即使首版单人使用，**将来启用多人协作亦无需数据迁移**（呼应 D7）。(3) **法律数据不容静默丢失**：字段值刻意选 **MV-Register 而非 LWW**，当两人并发修改同一单元格，系统**保留双值并上报人工裁决**，而非以最后写入获胜静默丢弃一份原始数据；对法律文件，暴露冲突交人工裁决远比自动覆盖安全。(4) **版本控制天然内建**：版本向量既是因果序、又直接充当数据版本，与出处账本无缝衔接。 |

## 17. 出处平面 Π：Merkle 出处账本与防篡改 [N]

为实现**防篡改**与**长期可复现**，所有已提交版本、绑定、样式与图片资产汇入一个**仅追加的 Merkle 出处账本** `ℒ`。

### 17.1 出处 DAG

`ℒ` 是内容寻址的有向无环图。每个提交节点：

```
commit ::= H( content_root ∥ parents* ∥ author ∥ logical_clock ∥ sig )
```

`content_root` 为该版本 SRDM 的 Merkle 根，`parents` 为前驱提交哈希（合并提交有多个父），`sig` 为签署者的数字签名。账本**仅追加**，撤销/重签作为**新提交**记录而非删除（呼应 LC5/SG）。

### 17.2 防篡改定理 [N]

```
 H 抗碰撞 某节点内容被改 其哈希改变
 ─────────────────────────────────────────────── (TAMPER-EVIDENT)
 所有引用其哈希的后继提交断链 ⟹ 篡改可被检出
```

数字签名覆盖 Merkle 根，使谁在何时担保了哪一版不可抵赖。LC2（归档后不可篡改）由该密码学性质**机制性保证**，而非仅靠访问控制。

### 17.3 双版本三元组与归档锚 [N]

每次出报告记录 `⟨模板版本, 数据版本, 绑定版本⟩`，三者各为 `ℒ` 中一个提交哈希，并嵌入 PDF/A 出处锚。任意历史报告可凭三元组在 `ℒ` 中**精确重建输入**，结合确定性定理⟹**逐位元复现十年前的报告**。

### 17.4 图片资产的内容寻址 [N]

本标准的 `BlobRef = cid(H(bytes))` 使图片成为账本叶子：相同图片去重、被多报告共享；图片字节任何改动都改变 `cid`、断开引用链。

> **设计依据 [I]（防篡改 + 图片 + 版本控制为何统一到 Merkle 账本）.** 报告是法律文件，事后不能被静默篡改单个数值或替换单张照片，是硬性底线。仅靠数据库权限是**可被绕过的事后约束**；Merkle 哈希链把不可篡改变成**密码学事实**：改任一字节都会断链且可被检出，签名使担保不可抵赖。图片以内容寻址入账本，既**去重**（同一原样照片多报告共享）又**防换图**。数据版本复用版本向量并锚为提交哈希，使**版本控制、防篡改、长期复现**三件事由同一棵 Merkle DAG 统一承载，这是把防篡改由声明落实为机制的根因设计。 |

## 18. 智能体平面 Α：面向 AI 智能体的可操作语义 [N]

为使 SRDF 文档资产**天然适配 AI 智能体**（自动填充、审阅、校对、版本管理、提建议），引入第四横切平面 Α。与 Ω/Σ/Π 一样，Α 与核心栈正交：它不新增文档语义，而是把AI 智能体作为受约束的参与者接入既有各层。

### 18.1 AI 友好的形式底座 [I]

AI 智能体之所以能高效操作 SRDF（而非操作 Word 二进制），根因在于 SRDF 把文档从非结构化文本变成形式对象：

- 文档是带类型的抽象语法树 SRDM，而非渲染后的字节流，智能体读到的是结构与语义，无需 OCR 或版面解析；
- 每个字段携类型、单位、角色、本体概念（Ω）与取值精化区间，智能体由此获得机器可读的可填值、单位与取值范围先验；
- 完整性约束是一阶逻辑（L5）、生命周期是时序/道义逻辑（L6），智能体的任何产出都有一个**可判定的对错预言机**（oracle）；
- 出处账本（Π）与协同（Σ）使智能体成为可记名、可合并、可回溯的一类副本。

### 18.2 智能体作为受约束的参与者：道义角色 [N]

AI 智能体在生命周期中获得专门角色 `Agent`，其权限/义务由道义逻辑（扩展 SG 公理）规定：

```
AG1 许可填充审校: P( Agent 提案: 填充 ∨ 审阅 ∨ 校对 ∨ 建议 )
AG2 禁止自治定签: F( Agent 执行: 签署 ∨ 定版 ∨ 归档 )      (* AI 绝不能成为终态权威 *)
AG3 人类背书义务: O( 人类审签 先于 任一 Agent 提案进入 Signed 态 )
AG4 提案须留痕:   G( Agent 任一变更 → ∃ 出处条目 ∧ 署名为 Agent 密钥 )
```

即 AI **可提议、不可终裁**；它的每一步都记名于 Π，与人类操作可区分。

### 18.3 五项能力的形式刻画 [N]

所有能力均遵循提案 → 形式校验 → 出处留痕统一管线，**绝不旁路** L5/L6/L7/Π：

| 能力 | 智能体动作 | 形式约束 / 校验 | 落点 |
|---|---|---|---|
| **填充 fill** | 依 Ω 概念与精化区间提议字段值、生成绑定候选（AUTO-BIND） | 类型/单位/区间（AI-REJECT）、绑定良定义（BIND-WD）、全有或全无（FILL-OR-REFUSE） | 写入 SRDM，过语义分析相校验 |
| **审阅 review** | 跨字段、跨章节一致性与结论合理性复核 | 一阶约束 Φ₀（C2/C5/C7）、本体一致性（⊑_DL） | 产出问题清单提案 |
| **校对 proofread** | 类型/单位/量纲/越界/缺填检出 | AI-REJECT、C2 必填、C5 量纲相容 | 标注违例，不自动改 |
| **版本管理** | 在 CRDT/Merkle 上做差分、合并建议、版本注释 | 收敛（SEC）、版本半格、出处账本 | Σ 副本提交 + Π 记名 |
| **提建议 suggest** | 以**类型化补丁对象**给出修改建议 | 补丁须使文档仍有效，否则拒绝 | 经人确认后并入 |

### 18.4 类型化提案与形式护栏 [N]

智能体的一切产出统一封装为**类型化提案** `Proposal`，而非自由文本：

```
Proposal ::= Patch(target : NodeId, op : EditOp,
                    payload : Value | Binding | Furniture, rationale : Text)
```

提案接纳的核心护栏：

```
   valid_S( apply(d, p) )    ∧    p 不触犯 AG2    ∧    出处记 author = Agent
 ──────────────────────────────────────────────────────────────────────────  (AGENT-GUARD)
                p 进入待人工确认队列；否则即时拒绝、不落库
```

即 **AI 提议、形式层裁决**：模型可能幻觉，但任何不满足类型/约束/本体/生命周期的提案在落库前即被 AGENT-GUARD 拦截，无法污染法律报告。这把 AI 的不确定生成与 SRDF 的确定性校验耦合成可信闭环（neuro-symbolic）。

### 18.5 机器朝向的能力接口 [N]

智能体经一组**带前置/后置条件的类型化操作**与文档交互，而非解析 PDF/Word：`query`（读本体、约束、字段先验）、`propose`（提交 Proposal）、`verify`（对文档跑全量静态校验）、`diff`/`merge`（版本）。该接口稳定且后端无关（P0）：任何智能体无论其内部实现，均经同一形式表面接入。

> **设计依据 [I]（为何 AI 友好却仍将 AI 约束于护栏之内）.** 化学部的将来方向明确含 AI 智能审核、历史数据分析。SRDF 使 AI 节省大量人工（初审、校对、填充、版本梳理），但报告是法律文件，故：(a) 形式底座（类型/本体/约束）给 AI 高质量的机器可读语境，使其建议更准确、更少臆测；(b) AGENT-GUARD 与 AG2 保证 AI 永远是提议者而非权威，幻觉被形式层拦截、定版必由人类签署；(c) Π 记名使经 AI 处理的字段永远可查，满足法律可问责。AI 友好与法律安全在此不矛盾，而由 AI 提议 / 形式裁决 / 人类背书三段式统一。

## 23. 需求 × 设计 × 理论对照（资料性）：关键设计为何如此

| 化学部需求 | SRDF 的关键设计 | 形式理论依据 |
|---|---|---|
