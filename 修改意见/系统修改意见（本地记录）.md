

## 1. 已形成的总体方向

1. 原始记录模板、数据录入、报告模板和报告生成应形成完整的数据链路，尽量通过映射自动带入，减少重复录入。
2. 编辑体验应接近 Excel 和 Word：支持键盘移动、多步撤销、连续文本编辑、自由表格、公式提示、复制粘贴和灵活排版。
3. 保存应自动进行，并在并发、断网、服务重启等情况下尽量避免丢失内容。
4. 未录入的数据在生成报告时原则上不应出现；空数据如何处理需区分普通字段、表格行列、试样和固定版式内容。
5. 模板修改不追溯覆盖已经生成的历史报告；新报告使用修改后的模板和映射。
6. 数据录入阶段允许调整部分内容，但必须保证后续报告映射仍能定位数据。
7. 英文报告、统一接口平台、设备接入平台和跨事业部数据隔离列入二期规划。

## 2. 权限、角色与协作

### 2.1 权限继承

- 测试主管应包含测试工程师的权限。
- 报告审核角色应包含文员的权限。
- 需要明确权限是通过角色继承实现，还是直接配置权限集合。

### 2.2 角色管理

- 用户管理中应支持角色管理，包括新建、修改、停用或删除角色。
- 删除角色前应检查是否仍有用户使用；有引用时应提示先迁移用户，避免产生无角色用户。

### 2.3 多人编辑

- 原始记录原则上不会由多人同时处理。
- 数据允许多人查看；是否允许多人同时编辑需要明确。
- 如限制单人编辑，应显示当前编辑人，其他用户只读，并明确谁写入“主检名称”。
- 如果以后开放多人编辑，需要处理编辑租约、冲突合并、版本记录和保存覆盖问题。

## 3. 自动保存、撤销和编辑状态

1. 所有编辑器建议每 10 秒自动保存，降低浏览器或服务器异常导致的数据丢失风险。
2. 自动保存不应中断当前编辑，也不应让页面退出编辑状态。
3. 数据发生变动但尚未保存、离开页面或切换模板时，应提供清晰提醒。
4. 所有编辑器应支持多步 `Ctrl+Z` 撤销以及恢复撤销；不能只记住一步。
5. “回到上一步”和“恢复到刚进入页面时状态”需要分别实现，避免两个按钮行为相同。
6. 需要评估编辑器内部撤回功能。如果对现有数据结构影响过大，可降低优先级。
7. “送审后撤回”属于业务流程撤回，需要调用接口通知业务系统撤销对应报告，不能只修改本地状态。

## 4. 通用界面和交互

1. 编辑卡片的关闭按钮统一放在右上角。
2. 表头编辑卡片的“确定”按钮放在卡片最底部。
3. 弹窗、抽屉和图片管理卡片应根据窗口高度自适应；内容过高时在卡片内部滚动，操作按钮保持可见。
4. 管理图片卡片目前可能超出屏幕，需要限制最大高度和宽度。
5. 图片标题应支持字体、字号等格式调整。
6. 全面检查白屏、页面无法滚动、错误状态显示不正确等界面问题，并补充统一错误边界和可恢复提示。
7. 数据录入时点击左侧录入项，应自动滚动并定位到右侧对应编辑位置。
8. 数据录入表格支持方向键、Tab、Enter 等键盘操作切换当前格子，减少鼠标点击。

## 5. 原始记录模板

### 5.1 模板建立和复用

1. 支持从其他模板派生子模板，保留母子关系。
2. 支持直接复制模板，复制结果与原模板相互独立。
3. 从原始记录建立项目模板时，应带入原始记录内容及已有映射，再由用户修改，而不是总从空白开始。
4. 从父模板或旧模板创建时，要避免母子关系使项目模板映射引用错误。
5. 公共区域不随普通内容重复复制，具体是复用同一份公共数据还是仅不复制显示，需要结合公共字段机制确定。
6. 原始记录模板修改后，是否同步更新对应项目模板需要明确。建议对尚未生成报告、且未人工改写的派生内容提供“更新映射/重新拉取”操作；已生成历史报告保持不变。

### 5.2 表头、行列和格子

1. 修复“允许录入时修改行列表头”已开启，但数据录入时仍无法修改行名的问题。
2. 表头可修改时，映射应按稳定位置或稳定标识符定位，不能因显示名称改变而失效。
3. 表头开关关闭后再次开启，应恢复原来状态。
4. 支持复制字段。
5. 表格编辑和自由表格能力应统一，包含插入、删除、调整尺寸、合并、拆分和映射配置时的自由调整。
6. 切换表格样式不能清空已经设置的内容、格子角色、公式或映射。
7. 原始记录自由表格的数字格式化需要复核和修复。
8. 需要确认“试录测试”功能是否被移除；如仍有业务价值，应恢复入口和结果预览。

### 5.3 数字格式和修约

- 数字显示方式应支持：
  - 小数位数；
  - 科学计数法；
  - 有效数字，例如 `93.9` 按两位有效数字显示为 `9.4×10¹`。
- 小数位数与有效数字是互斥选项，由用户选择其中一种。
- 修约不应强制另外设置小数位。
- 复核“四舍五入”“四舍六入五成双”和“向上修约”的实现。
- 不需要提供向下修约。

### 5.4 单位和判定要求

1. 单位选择与判定要求选择应拆成两个独立组件。
2. 数字或文本字段的单位可以在模板中配置多个可选值，由录入人员选择实际单位。
3. 判定标准允许放在表格或表头中，并可通过选择直接显示。
4. 需要明确判定要求、限值和结论之间的数据关系，避免只保存显示文字而无法自动判断。

### 5.5 结论分区

结论分区的默认字段建议为：

1. 名称或子项目名称；
2. 判定要求；
3. 限值；
4. 结论。

一个原始记录包含多个子项目或多个结论时，在结论分区中明确每个项目名称、对应限值和结论，报告映射按稳定标识提取。

### 5.6 自动限制判定

希望支持根据限值自动生成单个试样或子项目的判定结论。实施前需要明确：

- 被判断的数据格或参数如何标记；
- 限值是固定值、录入值还是区间；
- 大于、小于、区间内、区间外等运算规则；
- 缺失值、文本值、单位换算和修约后数值如何处理；
- 多个指标如何汇总为一个结论；
- 自动结论是否允许人工覆盖，以及覆盖后如何记录。

建议为自由表格格子增加稳定角色，如“被判定值”“下限”“上限”“结论输出”，由规则引用角色或稳定格子标识，不直接依赖显示位置。

### 5.7 样品描述

- 增加专门的样品描述表格，支持结构化录入和报告映射。
- 需要确认样品描述是一份报告共用、一个样品一条，还是一个项目下可以有多条。
- 样品描述表格与首页“样品描述”字段之间应建立明确的汇总或覆盖规则。

## 6. 公式编辑

1. 表格公式参考 Excel，输入 `=` 触发公式编辑。
2. 使用 `A1`、`D3` 等坐标引用格子。
3. 输入函数或字段时提供自动补全提示。
4. 选择或拖动一片区域时自动写入范围，例如 `A1:A5`。
5. 公式编辑期间高亮所有被引用格子，并用不同颜色区分多个引用范围。
6. 编辑器上方提供固定公式栏，显示当前格子的公式，减少在浮动卡片和表格之间来回移动。
7. 数据录入时公式应实时计算并显示结果，便于工程师使用中间结果继续录入或判定。
8. 需要提供公式错误提示，包括循环引用、无效坐标、类型错误和除零。

## 7. Excel 导入与复制

1. Excel 导入时只要求用户填写 Sheet 名称，系统自动寻找合适区域。
2. 自动识别不正确时，允许用户在导入卡片中调整导入范围和表头对应关系。
3. 表头参数名称应与 Sheet 中对应，否则系统可能无法自动识别；需要在界面中明确显示未匹配项。
4. 自动导入仍不正确时，允许直接从 Excel 复制粘贴表格。
5. 需要说明为什么某些场景必须导入表头，以及表头不一致的具体实例。
6. 需要确认数据录入阶段增删行列、修改表头的真实业务场景，再决定动态操作的开放程度。

## 8. 数据录入

### 8.1 接口数据和自动带入

1. 原始记录服务编号和样品编号自动从接口拉取，同时允许人工修改。
2. 项目名称从委托单接口获取，并显示在原始记录和报告中；正式实施依赖能力库。
3. 原始记录检测时间从接口的送检日期 `SendDate` 获取。
4. 接口字段、检测时间和审核时间都应作为可绑定的数据来源。
5. 委托单接口返回的信息应显示在数据录入页面，方便录入人员参考，不必另行查询。
6. 需要核对接口返回的页眉、页尾、校验码、报告编号和签署区域备注是否对应当前报告。

### 8.2 空值处理

1. 录入页面中未填写字段可以显示斜杠作为视觉提示，但应区分“真实值为斜杠”和“未填写”。
2. 报告生成时默认不拉取未填写内容。
3. 需要分别确认以下内容为空时的处理：普通字段、表格单元格、整行、整列、试样、图片说明和结论。
4. 试样行或列没有任何有效数据时，不应生成对应报告行列。

### 8.3 动态行列、参数和试样

- 数据录入时希望参数数量、试样数量和部分表头可以调整。
- 动态增加的数据可能没有预先配置的报告映射。建议采用稳定参数标识和试样标识，并为报告模板提供：
  - 按参数角色绑定；
  - 按试样区域整行或整列展开；
  - 未识别参数的兜底区域；
  - 生成报告前的映射缺失提示。
- 根据已有讨论，不宜开放过多任意动态操作，应保留业务确实需要的增删改能力。

### 8.4 图片和附件

1. 数据录入时图片可以新增、删除、替换、旋转和调整尺寸。
2. 图片可以修改标题或名称。
3. 图片或表格可填写备注，也可以不填。
4. 所有图片应能按映射拉取到报告；单数布局时第一张默认位于最上方。
5. 手机和平板支持直接拍照上传；电脑端使用文件上传。
6. 普通附件支持任意文件类型的上传、下载和删除。

### 8.5 设备搜索

- 检查设备搜索匹配不准确、出现无关设备的问题。
- 搜索应明确匹配字段、排序规则、停用设备过滤、所属部门过滤和无结果状态。

## 9. 项目模板和映射

### 9.1 从原始记录拉取

1. 创建项目模板并关联原始记录后，默认带入原始记录的表格、字段、图片分区和映射。
2. 新建项目模板关联后无需再次点击“开始编辑”才看到内容。
3. 编辑项目模板时可以打开和查看对应原始记录模板。
4. 项目模板数据来源中应包含检测时间、审核时间以及接口提供的可映射字段。
5. 保存、保存并结束编辑、送审之间的流程和按钮需要统一，避免按钮重复或结束编辑后没有送审入口；原始记录模板也需要采用相同逻辑。

### 9.2 映射界面

1. 空格子只显示简洁的 `+`，不在每个格子中重复显示“添加映射”。
2. 格子已有文字时，不在文字下方继续显示“添加映射”，即使单位映射尚未配置。
3. 修复公式绑定后格子文字显示两遍的问题。
4. 试样区域支持按整行或整列绑定，不要求逐格配置。
5. 从原始记录拉取映射时，如果原始记录采用“每行一个试样”，默认生成按列展开的试样区域；反向结构同理。
6. 选择映射时，可先框选报告区域，再选择试样行或列来源，系统自动建立整片区域映射，无需提前单独设置试样区。
7. 参数表头支持按行或列直接绑定，试样区域内部格子根据规则自动展开。
8. 映射应使用稳定标识，不仅依赖表头显示名称，以支持录入阶段修改表头。

### 9.3 主机厂专有字段

不同主机厂可能要求增加专有字段。希望在生成报告时按主机厂配置动态添加，避免把相同字段分别维护在所有项目模板中。需要设计主机厂级报告片段或字段组，并定义插入位置和覆盖规则。

## 10. 报告首页模板和项目模板

1. 首页模板和项目模板都可以关联主机厂。
2. 同一主机厂的首页模板和项目模板可以放入项目组，项目组仅用于管理，不是生成报告的必要条件。
3. 需要明确首页项目组与项目模板项目组的类型规则，避免加入首页模板时误报“报告模板类型与项目组类型不一致”。
4. 创建模板或项目组并关联主机厂后，列表必须正确显示关联状态。
5. 报告首页模板如何参与继承、修改和历史版本管理，需要与项目模板保持一致的规则。
6. 项目模板修改后如何更新尚未签发的报告，建议提供明确的“重新应用模板/刷新映射”操作，不自动覆盖人工编辑内容。

## 11. 报告生成和编辑

### 11.1 数据选择和生成

1. 报告生成应使用当前已有且有效的样品和项目，不因部分样品或项目缺失而阻止整份报告生成。
2. 一个项目关联多个测试方法时，不同测试方法应作为独立报告项目，并保持业务规定的顺序。
3. 同一份报告的多个项目都应可选、可生成，不能只显示第一个项目。
4. 调整报告样品或项目后应立即生效。
5. 在报告编辑器中查看原始记录时，应能查看该报告关联的全部原始记录，而不是只能查看一份。
6. 需要明确“一项目对应多原始记录”和“一原始记录对应多项目”的实际场景、排序、结论和出报告规则。

### 11.2 连续编辑体验

1. 报告编辑器应尽量接近 Word，文字、表格和图片处于连续文档流中。
2. 分区标题、“样品描述”等文字可以选中、编辑、换行，并能在前后插入或删除空行。
3. 在字段最前面按 Backspace/Delete 时，可以删除上方可删除的空行。
4. 图片和表格可以选中、移动，在前后插入段落。
5. 左侧编辑器与右侧 PDF 的字体、字号、行距、段前段后和分页结果应尽量一致。
6. 支持单栏和双栏排版；普通文字和字段可进入双栏，图片和表格默认跨栏或保持单栏完整显示。
7. 备注换行应在编辑器和 PDF 中保持一致。

### 11.3 报告图片

1. 原始记录图片分区映射应在拉取模板时默认配置。
2. 图片默认采用粘连布局，但一页放不下后续图片行时必须自动分页。
3. 图片编辑只保留实际需要的表内标题；不自动生成无来源的加粗说明或备注框。
4. 没有填写的图片备注不应在报告中生成“备注”段落。
5. 支持用户调整项目之间是否强制分页，不能只能使用“一项目一页”的固定规则。

### 11.4 报告固定信息

- 检查报告右上角校验码、编号等是否取自正确接口和当前报告。
- 检查签署区域、备注、页眉和页尾是否取自正确接口或模板。
- 检查首页所有字段是否真正来自接口，重点包括检测周期、送检日期和项目名称。
- 报告结尾是否统一增加判定规则说明及报告结束分隔线，需要确认是否适用于所有报告。

### 11.5 报告编号

- 排查接口报告编号、本地报告编号、PDF 显示编号和回传编号不一致的问题。
- 编号应有单一来源，并在生成、签发、下载和回传全过程保持一致。

## 12. 主机厂、项目组和项目名称

1. 创建模板和项目组时关联主机厂后，条目必须显示正确的主机厂名称。
2. 原始记录名称过长时不能覆盖主机厂名称，列表布局应换行、省略或提供悬浮完整内容。
3. 项目名称自动显示依赖能力库；能力库完成前保留接口字段和映射位置。
4. 项目名称与结论的关系应在原始记录结论分区中定义，支持子项目名称和对应结论。

## 13. 日期和时间

需要统一以下时间字段的来源和格式：

- 送检日期；
- 检测日期或检测时间；
- 审核日期或审核时间；
- 报告签发日期。

需要确认哪些字段只显示年月日，哪些需要显示年月日时分。建议模板字段提供格式选项，例如：

- `YYYY-MM-DD`；
- `YYYY年M月D日`；
- `YYYY-MM-DD HH:mm`；
- 仅时间 `HH:mm`。

日期格式属于显示配置，原始数据仍保存完整时间值。

## 14. “常用值不进报告”规则

部分字段希望设置“常用”选项：

- 模板中显示常用内容作为录入提示或默认值；
- 录入人员仍能看到并选择；
- 如果实际值等于配置的常用值，报告中可以不体现；
- 非常用值才生成到报告中。

该规则需要同时存在于原始记录字段和报告映射中，并明确“默认值”“提示值”和“已录入值”的区别，防止系统把未确认的提示内容当作真实数据。

## 15. 系统稳定性、并发和数据架构

1. 优化并发访问、数据库连接池、PDF 生成队列和静态资源加载。
2. 检查无原始记录模板时登录页出现“0!”提示的问题，应显示正常空状态。
3. 没有订单时，生成报告页面不能持续转圈，应正确结束请求并显示空状态。
4. 数据库与应用服务分离部署，数据库使用独立持久化存储和备份策略。
5. 页面白屏时提供统一错误页面、错误编号和重新加载入口。
6. 长列表、图片、PDF 和大型表格需要控制内存占用，避免页面无法滚动或浏览器卡死。

## 16. 已讨论的取舍和依赖

1. 多个子项目和结论采用原始记录模板中的专门结论分区解决。
2. 项目名称自动关联等待能力库完成。
3. 英文报告放在二期，建议通过原模板的英文子模板实现，需要工程师提供参考模板。
4. 页眉 CNAS Logo 由业务系统处理。
5. 数据录入阶段不做过多任意动态操作，优先保留确实需要的行列、表头和试样调整。
6. 更换原始记录模板会覆盖原模板结构，已录入数据需要重新录入；当前讨论认为此逻辑可以接受，但界面必须提前警告。
7. 模板新修改不追溯更新已经生成的历史报告。
8. 接口字段标准化和跨系统能力统一放入二期平台规划。

## 17. 二期规划

## 19. 建议的复核和实施顺序

### 第一阶段：先确认现状和修复明显问题

- 空状态出现“0!”或无限加载。
- 表头允许修改但录入时无法编辑。
- 表格样式切换丢数据。
- 自由表格数字格式错误。
- 保存、结束编辑和送审按钮逻辑。
- 项目模板关联后内容不立即显示。
- 设备搜索错误匹配。
- 弹窗超高、白屏和无法滚动。
- 报告编号、校验码、页眉页尾和接口数据不一致。

### 第二阶段：统一编辑能力

- 10 秒自动保存和编辑状态连续性。
- 多步撤销、恢复撤销及离开提醒。
- 键盘录入、公式栏、区域选择和实时计算。
- 表格样式无损切换、自由合并和稳定标识。
- 图片标题、备注、旋转、尺寸和分页。

### 第三阶段：完善数据链路

- 接口字段统一进入映射来源。
- 原始记录到项目模板的内容及映射继承。
- 动态试样区域整行、整列映射。
- 多测试方法、多原始记录和多项目生成规则。
- 空值过滤、主机厂专有字段和模板刷新机制。

### 第四阶段：业务规则

- 结论分区四字段模型。
- 自动限制判定。
- 常用值不进报告。
- 日期格式和修约规则。
- 权限继承、角色管理和流程撤回。
